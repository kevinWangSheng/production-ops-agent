- **D1 生成门槛与陈旧**：只有观察会话已结束且有最终恢复投影时才可生成。草稿绑定事故控制代际、观察代际、Run/输入水位与证据快照哈希；之后 reopen、恢复判定变化、追加 Run 或新证据使草稿 `stale`（记原因），不可审核，只能重新生成新版本。
- **D2 内容来源**：事故标识、时间线、Run 状态、人工控制、恢复观察、证据引用与所有数值由代码从 PG 确定性拼装；模型只写影响摘要、发现叙述、假设/反证与建议。每个模型段落绑定证据 ID、scope、时间窗与 `citable_as_fact`（只有可作事实引用的证据才能支撑事实陈述）；引用校验失败的段落标为不确定并阻止提交审核。每次生成尝试最多两次有界真实模型调用（一次生成 + 至多一次结构/引用修正，r3 D22）；供应商失败的重试是新的生成尝试，次数与预算见 D22、D23、R7。验收用确定性断言，LLM judge 不替代。
- **D3 争议**：每条结论带 `certainty` 与 `dispute_state`（含原因与提出者）；存在争议的结论阻止批准；模型分数、自评与自动任务不能清除争议。草稿、审核中、驳回、陈旧均在审核页可见；任何知识读取只返回状态为 `active` 的审核版本（`superseded`、`revoked` 均不返回）。
- **D4 知识形态**：两层——整篇结构化复盘供审阅；从中抽出的结构化知识条目（症状、检查、证据引用、名称、标签）供 M2 按名称/标签/全文检索，结果带 revision、来源、证据引用与 freshness（PRODUCT-CONSTRAINTS 第 30 行）。
- **D5 审核状态机**：动作为批准、驳回、退回修改、替换（supersede）、撤销。退回修改生成新草稿版本、原版只读；批准后内容不可编辑；替换通过新审核版本完成；撤销是单独人工动作，保留墓碑与理由，不改写已引用它的历史报告。
- **D6 审核者**：审核动作只接受经 Basic Auth 认证的 web 主体，持久化 `actor_id`、认证主体类型与时间；worker、模型、Observer 无法调用审核接口。草稿由 worker 自动生成（D1、D14、D15），没有人工作者，因此不存在「同一人生成并审核」。
- **D7 版本与不可变**：同一知识条目内单调整数版本，内容哈希固定；数据库层仅追加，拒绝对已批准版本 UPDATE/DELETE（触发器或角色权限）。撤销只改变可检索状态。
- **D8 权限（2026-10-09 实施中修订）**：web 与 worker 共用迁移 owner 角色（同一 `OPSPILOT_DSN`），owner 不受 GRANT 约束，原「库层分 worker/web 写权限」无法落地。用户裁决按 M1-02 先例：库层只落对 owner 也生效的部分——已批准版本、知识 revision 与审计只追加，触发器拒绝 UPDATE/DELETE，撤销只追加墓碑；Observer 对 F13 表零写权限并实测。这沿用 M1-01/M1-02 现状——调查侧 Controller/Worker/Gateway 的 C3 §3 角色隔离不在本切片（已知偏离，见 M1-02 记录计划第 74 行与 #169）；worker 的写入经存储层的 Controller 侧原语提交，与 M1-02 Observer 授权同一做法。worker/web 分工在代码层落实：审核原语只在 web 模块，生成模块不引用（AST 测试把守）。不新建角色。触发器防代码错误，不防 owner 凭据泄露；调查侧角色拆分见 #169。迁移遵循 C3 §11（停 web、worker、Observer 后迁移，迁移后 `verify_head`）。
- **D9 变更接口**：复盘/知识对象有独立代际；生成、批准、驳回、退回、替换、撤销都要求预期代际、独立幂等键与操作者审计，状态、事件与引用在同一事务内提交，与事故控制代际解耦。
- **D10 范围与 passes**：见「目标与范围」。
- **D11 验收投影**：在外部验收结果中新增复盘与知识字段（草稿状态/版本、生成水位、每节事实与证据引用、不确定与争议、审核动作、审核者类型与 ID、知识 revision 与状态、替换/撤销、陈旧原因）；照 F6 `recovery_outcome` 只复制已提交记录，主体不一致返回 unknown；没有记录时为 `not_generated`。工作台页面与投影一致，不另算。
- **D12 保留期（移出 M1）**：只立约束——将来实现清理时，被知识引用的复盘、审核审计与证据最小元数据必须固定保留或留墓碑，不得悬空。
- **D13 知识快照与隔离（移出 M1）**：随第 4 步放 M2。
- **D14 退回后的新版本（2026-10-09 实施中补）**：只能由 worker 重新生成，可带审核者退回理由作输入；人不直接编辑内容。
- **D15 提交审核（同上）**：引用校验全部通过的草稿由 worker 生成后自动进入审核中；人只做 D5 的五个动作。生成与提交只接受 worker 主体，五个审核动作只接受 Basic Auth 主体。
- **D16 争议不可清除（同上）**：争议只追加，任何主体都不能清除；有争议的版本只能退回或替换成新版本，不能批准。
- **D17–D27（r3）**：独立复盘候选扫描与专用生成租约；改变水位的事务同步标 stale；退回写待重新生成标记；复用 `deepseek-flash` 但独立 prompt 版本；模型输入白名单、脱敏与上限；引用失败一次修正后停在 draft、供应商失败只记生成尝试；独立生成预算；真实证据只在实验环境；替换走批准提议；第 2 步先冻结快照与命令数据结构；已结束观察的旧事故一视同仁生成。逐项见决定表。
