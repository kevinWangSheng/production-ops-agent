模块 `opspilot/observation/releases.py`（新文件）：

```python
Sha256Digest  # 字符串，^sha256:[0-9a-f]{64}$

class ReleaseRevision(DTO):
    images: dict[Text, Sha256Digest]        # 容器名 -> image digest，至少 1 项
    pod_template_digest: Sha256Digest       # 完整 pod-template/config 规范化摘要

class ReleaseAuxiliary(DTO):                # 全部可选，仅辅助证据，不参与唯一性
    deployment_uid: Text | None = None
    before_replicaset_uid: Text | None = None
    after_replicaset_uid: Text | None = None
    before_pod_template_hash: Text | None = None
    after_pod_template_hash: Text | None = None
    deployment_generation: Count | None = None

class ReleaseEvent(DTO):
    format_version: Literal[1]
    source: Text
    source_release_id: Text
    released_at: AwareDatetime              # 部署源实际提交该次变更的时间（P1-01）
    before: ReleaseRevision
    after: ReleaseRevision
    auxiliary: ReleaseAuxiliary = ReleaseAuxiliary()

class ReleaseReceipt(DTO):
    outcome: Literal["created", "replayed", "rejected"]
    observation_id: UUID | None             # rejected 且无原记录时为 None；冲突时指向原记录
    event_id: int                           # 本次投递的审计行
    status: str | None                      # 记录当前状态；rejected 无记录时 None
    reason: str | None                      # rejected 的原因码；created 为 None 或 "late_delivery"

class ReleaseRecord(DTO): ...               # 记录的全部冻结字段与状态（字段名同表列）
class ReleaseEventRecord(DTO): ...          # 审计行（字段名同表列）

class ReleaseStore(_StoreBase):             # 构造同 ObservationStore(dsn)
    def record_release_in(self, conn, *, event: ReleaseEvent, target_id: UUID,
        identity: Mapping[str, str], health_profile_revision: str, health_profile: str,
        min_tracking_seconds: int, actor: str, raw_body: bytes) -> ReleaseReceipt
    def record_release(self, **同上去掉 conn) -> ReleaseReceipt   # 自开自提交的事务包装
    def get_release(self, observation_id: UUID) -> ReleaseRecord  # 不存在 -> PersistenceError("NOT_FOUND")
    def find_release(self, source: str, source_release_id: str) -> ReleaseRecord | None
    def release_events(self, observation_id: UUID, *, after: int = 0) -> tuple[ReleaseEventRecord, ...]
```

固定语义：
- `identity` 与 `target_id` 来自配置的目标身份注册表（同 `register_remediation` 的 `identity` 参数），与登记行的补齐与比对规则、错误码沿用现有实现（`TARGET_MISMATCH`、`TARGET_IDENTITY_MISSING`、`HEALTH_PROFILE_TARGET_MISMATCH`），不得从 `event` 取任何目标身份。`TARGET_UNRESOLVED`/`TARGET_AMBIGUOUS` 属 PR-3 解析器，本步不出现。
- `health_profile_revision` + `health_profile`（规范化内容）按现有 `opspilot_health_profiles` 规则校验与去重；冻结 cadence、持续窗、`deadline_seconds`、`max_samples` 及 revision。`min_tracking_seconds` 必须显式传入、无默认（P1-02）。
- 时间：`received_at` 取 DB `clock_timestamp()`；`deadline_at = released_at + deadline_seconds`；`released_at > received_at`（零容差）→ rejected `RELEASE_TIME_IN_FUTURE`；`max(min_tracking_seconds, sustained_window_seconds) >= deadline_seconds` → rejected `INVALID_RELEASE_POLICY`；`received_at >= deadline_at` → created，状态 `unknown`，`reason="late_delivery"`；否则 created，状态 `pending`。
- 幂等（P1-03）：唯一键 `(source, source_release_id)`。同键再投递：语义指纹（目标 + before/after + released_at + auxiliary 的规范 JSON sha256）一致 → `replayed`，返回原记录，不改任何字段、不重置时间；不一致 → rejected `RELEASE_IDENTITY_CONFLICT`，`observation_id` 指向原记录，原记录不变。并发首投由唯一约束裁决（P1-11）。
- 业务拒绝（上述原因码，以及目标/profile 的三个错误码）返回 `rejected` receipt，并在同一事务提交审计行；存储故障抛 `PersistenceError`（`RETRY`/`TIMEOUT`/`STORAGE_UNAVAILABLE`/`INTEGRITY_REFUSED`）并整体回滚。`ReleaseEvent` 结构非法由 pydantic 在进入存储前拒绝，不写任何行。
- 审计（P1-08）：每次 `record_release*` 调用恰好追加一条 `opspilot_release_events`：outcome、reason、source、source_release_id、actor、DB `received_at`、`raw_sha256 = sha256(raw_body)`、`semantic_sha256`、`audit_text`（`raw_body` 按 UTF-8 解码后经现有凭据脱敏，限长 16 KiB，`truncated` 标记）；有记录的行带 `observation_id` 与按记录递增的 `sequence`。
- 不在本步：HTTP 路由、观察会话、采样、状态推进、取消、暂停、事故关联、F11 投影、`passes`。

## 预审原文（决定表裁决列已填）

PR-1 应限定为**发布事件的数据合同、独立 `ReleaseObservation` 持久化及可组合的 store 写入原语**，不接 HTTP、不创建观察 session、不启动采样。session/ending 的 `incident_id NOT NULL`、sample 主体绑定、Observer 状态采纳及权限扩展均留给 PR-2；webhook、认证主体绑定、载荷解析和发布 harness 留给 PR-3。这与[拆步记录](docs/tasks/2026-10-12-f11-post-release-contract.md:90)一致，也避免只放宽空值而遗漏当前领取 SQL 的 incident JOIN。迁移应为 `0014`，前置 `0013_self_heal_authorization`。**PR-1 可以有公开 Python store 写入口，但它不是完整事件接收入口**；PR-3 必须在同一事务中组合事件、发布主体和观察任务，提交后才能确认接收（C3:229）。
