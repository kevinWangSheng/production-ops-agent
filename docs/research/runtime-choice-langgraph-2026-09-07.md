## Findings and source chain

1. **A graph does not imply symptom routing.** StateGraph accepts arbitrary nodes and conditional continuation. A model node and authorized tool node can repeatedly exchange observations; symptoms need not be graph nodes or classifiers. The official interrupt example itself uses agent/tool continuation based on tool calls. Therefore LangGraph is compatible with ADR-0002. Prompt, context assembly, relevance selection and investigative competence still belong to our implementation, not the runtime. [Official overview](https://docs.langchain.com/oss/python/langgraph/overview), [official loop example](https://docs.langchain.com/oss/python/langgraph/interrupts).

2. **Persistence is execution-state persistence, not an incident product.** Caller compiles with a checkpointer and supplies thread_id. PostgreSQL saver fetches by thread/namespace/checkpoint and writes graph values plus blobs. A durable backend is available; memory saver is not restart persistence. Source: [Postgres get/put](https://github.com/langchain-ai/langgraph/blob/81bf17b23123e4ef8b9d5f49fa09a0122fc2edd1/libs/checkpoint-postgres/langgraph/checkpoint/postgres/__init__.py#L227-L346). Incident identity, event deduplication, human correction precedence, investigation run identity, evidence retention and recovery observation are application contracts; merely mapping Incident to thread_id does not implement them.

3. **Durability has selectable loss/performance tradeoffs.** Source defines sync (persist before next step), async (persist alongside next step), exit (persist on exit); stream default is async. Sync caller explicitly waits on checkpoint future, loop chains writes to saver. Source chain: [type](https://github.com/langchain-ai/langgraph/blob/81bf17b23123e4ef8b9d5f49fa09a0122fc2edd1/libs/langgraph/langgraph/types.py#L89-L96), [default](https://github.com/langchain-ai/langgraph/blob/81bf17b23123e4ef8b9d5f49fa09a0122fc2edd1/libs/langgraph/langgraph/pregel/main.py#L2597-L2605), [wait](https://github.com/langchain-ai/langgraph/blob/81bf17b23123e4ef8b9d5f49fa09a0122fc2edd1/libs/langgraph/langgraph/pregel/main.py#L2984-L2988), [write](https://github.com/langchain-ai/langgraph/blob/81bf17b23123e4ef8b9d5f49fa09a0122fc2edd1/libs/langgraph/langgraph/pregel/_loop.py#L1530-L1548). Inference: sync reduces checkpoint loss windows but adds database wait; it does not transactionally include external calls. A query can complete before its recorded result is committed; retry can repeat it. Exit is unsuitable as the default for our long investigation crash requirement; async needs an explicitly accepted recovery window.

4. **Resume is replay of execution units, not restoration of a running call stack.** interrupt throws a resumable exception; Command(resume=...) uses stored resume values and starts the interrupted node again. Code before interrupt executes again; multiple interrupts depend on order. [Implementation contract](https://github.com/langchain-ai/langgraph/blob/81bf17b23123e4ef8b9d5f49fa09a0122fc2edd1/libs/langgraph/langgraph/types.py#L851-L873). Upstream test verifies saved successful parallel node is not rerun while failed node retries: [test](https://github.com/langchain-ai/langgraph/blob/81bf17b23123e4ef8b9d5f49fa09a0122fc2edd1/libs/langgraph/tests/test_pregel.py#L892-L992). Test was read, not executed. Application must choose replay-safe boundaries, record query attempts and distinguish fresh/reused evidence. Checkpoints do not restart dead workers; an external service must redispatch recoverable runs.

5. **Cancellation is not hard process termination.** Sync executor cancels futures then waits for pending tasks; async executor cancels asyncio tasks then awaits them. [Sync](https://github.com/langchain-ai/langgraph/blob/81bf17b23123e4ef8b9d5f49fa09a0122fc2edd1/libs/langgraph/langgraph/pregel/_executor.py#L92-L108), [async](https://github.com/langchain-ai/langgraph/blob/81bf17b23123e4ef8b9d5f49fa09a0122fc2edd1/libs/langgraph/langgraph/pregel/_executor.py#L185-L200). Therefore arbitrary blocking SDK calls/processes need their own deadlines, cleanup and isolation. interrupt is a planned human-input pause, not a universal immediate stop button. Our pause/cancel API needs state precedence and protection against late completions.

6. **Python reuse advantage is real but dependency-free is false.** At this revision package depends on langchain-core, checkpoint, SDK, prebuilt, pydantic and xxhash, though application need not use high-level LangChain agents. [Manifest](https://github.com/langchain-ai/langgraph/blob/81bf17b23123e4ef8b9d5f49fa09a0122fc2edd1/libs/langgraph/pyproject.toml#L5-L33). Arbitrary Python model-client nodes are possible; provider compatibility, tool schema/stream normalization and instrumentation need adapters. Python makes Holmes/OpenSRE logic reuse easier; TS LangGraph is a separate package and requires its own version/parity audit rather than assuming these Python findings hold unchanged. [Postgres dependencies](https://github.com/langchain-ai/langgraph/blob/81bf17b23123e4ef8b9d5f49fa09a0122fc2edd1/libs/checkpoint-postgres/pyproject.toml#L5-L18).

7. **Library, observability and Deployment are separate choices.** MIT LangGraph library can be embedded in our own service. LangSmith tracing is optional, not necessary to run the graph; custom instrumentation remains possible. LangSmith Deployment / Agent Server provides a separate service layer. Current official page describes Cloud, hybrid and self-hosted deployment, including license requirements for standalone Agent Server; do not attribute its queue/hosting capabilities or pricing to the MIT library. [Deployment](https://docs.langchain.com/langsmith/deployment). LangSmith observability/eval can also be selected with other runtimes. No SaaS/platform selection is made here.

## Recommendation and limits

Recommend LangGraph Python as a strong candidate if durable investigative step state and human resume are required from the outset. Its concrete advantage over a handwritten while-loop is existing checkpoint/replay/retry/stream machinery with examinable tests. Use a small shared model/tool loop, not symptom graphs and not a second competing incident database hidden inside graph state.

Still our responsibility: incident lifecycle and run admission; scheduler/recovery dispatch; locking or leases and backpressure; target authorization and query budgets; tool-process cleanup; evidence provenance and retention; authentication/UI; metrics/redaction; independent recovery checks; reviewed knowledge; evaluation and deploy/restore tests. PostgreSQL checkpointing does not replace these duties or automatically make incident updates and checkpoints one atomic transaction.

Costs: graph/node/reducer semantics, checkpoint schemas and version compatibility, database lifecycle and retention, framework dependencies, replay-safe coding, migration tests, diagnostic complexity. Avoid wrapping a fully self-contained HolmesGPT loop in one giant node merely to claim durability: this only checkpoints outside that loop. Splitting it must preserve its actual investigation behavior and be worth the adaptation cost.

Reverse the recommendation if existing upstream loop can be reused much more faithfully with a lighter runtime, if checkpoint/replay controls add little beyond our mandatory incident/run store, or if Python conflicts with the chosen integration stack enough to erase the reuse benefit. No claim that LangGraph improves model accuracy by itself.

## Small validation needed before final adoption

Run one dynamic model/tool cycle with deterministic fake tools, then real provider smoke test; kill worker between tool result and checkpoint; restart and verify precise repeat/freshness semantics; interrupt/resume across process; human cancel followed by late result; synchronous blocking tool and async timeout cleanup; database outage; state schema update; export redacted traces without requiring LangSmith hosting. These are proposed technical experiments, not completed evidence or authorization to implement product features.
