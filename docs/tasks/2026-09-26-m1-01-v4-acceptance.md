## 决定与理由（Agent 自决，可逆）

1. 独立观察脚本自写（`observe.py`），直接读 Prometheus 即时查询与 Jaeger `/api/traces`，与产品 transport 无共享代码，以保证与产品 Run 分离。
2. 四次提交使用同一段症状问题（沿用 6a 冒烟措辞），不区分正常/故障，避免向调查者泄露案例类型。
3. 账本导出把 `reasoning_content` 置换为固定占位、raw 只记 sha256 与长度（C3 §12 与 6a 同规）。
4. 审查者拿到执行者的 `handoff-cause.md` 所在目录但被明确要求不读它，并自行离线复跑 `parse_report` / `unsupported_citations`。

## 待决（用户）

1. **M1-01 完成定义**：v4 包 0/4 不通过。选项：(a) 按现状记不通过，先处置下面两项产品合同问题再授权新的 2+2；(b) 收紧/澄清判据后重跑（判据只能收紧，不能为迁就实现放松）。
2. **合同层取舍——`no_data` 视图能否支撑「缺失」事实**：`unsupported_citations` 要求 fact 类 claim 只引用 `status == "ok"` 视图，该规则不在任何模型可见合同、设计文档、C3 或测试中；三份交接里两份直接由此触发、第三份反事实复跑也会被拒。可选：写进 `REPORT_CONTRACT`；或允许 `no_data` 支撑 absence 事实；或只拒单条 claim 并给一次重试（涉及预算规则）。
3. **`otel-demo` metrics 工具描述与窗口语义**：描述承诺越窗读取被拒，实际允许范围选择器在窗口起点回看自身长度，`source_start_at` 低估源范围（normal-1 P2-3）。是收紧 transport 还是改描述与 `source_start_at`，属工具合同取舍。
4. 次要：视图同时暴露 `operation_id` 与 `evidence_id`（fault-2 引用截断的诱因）；交接/发布后工作台显示事故 `state queued`（未确认是否有意）。
