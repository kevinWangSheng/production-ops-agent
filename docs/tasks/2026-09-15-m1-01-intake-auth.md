## 本次范围

- 用严格、不可变类型表示已由可信认证适配器验证的操作者身份。
- 明确 UI Basic Auth 与事件 token 是两个不能互换的认证通道。
- 表达 target、question、idempotency key、request id 和接收时间。
- 幂等比较绑定操作者、认证版本、目标和问题；同 key 的不同身份/内容不会静默合并。
- 凭据、密码、原始 header/token 不进入产品对象，也不进入校验失败时的异常消息。
- 身份、目标、请求标识和幂等字段统一拒绝会造成审计歧义的文本，避免后续审计/日志歧义。

### 自测发现并修复的两项缺陷

两项均先复现、再修复，并补了在修复前为红、修复后为绿的回归测试。

1. **控制字符拒绝范围不足**（`opspilot/intake.py:74`，提交 `8a6bd5a`）。
   `4bcc6ee` 声称 "reject all unicode control characters"，实际只判断 `category(char) == "Cc"`。
   实测 `U+00AD`、`U+200B`、`U+200E`、`U+202E`、`U+2066`、`U+2028`、`U+2029`、`U+FEFF`、
   `U+E0001` 全部通过校验。双向覆盖符会让存下来的身份在审计行里渲染成另一个身份，
   `U+2028`/`U+2029` 会把一条审计记录切成两条，正是该字段守卫声称要防的歧义。
   改为拒绝 `Cc`/`Cf`/`Zl`/`Zp`；同时补一条用例固定「普通非 ASCII 文本仍然接受」。
   **已知取舍**：整类拒绝 `Cf` 也会拒绝部分文字在正常行文中使用的 ZWJ/ZWNJ。
   这些字段都会渲染进面向操作者的审计行，此处选择失败得响亮而不是留下渲染歧义；
   若后续出现真实的多语言提问需求，此取舍需要重新评估。

2. **校验失败的异常消息回显被拒绝的输入**（`opspilot/domain/base.py:38`，提交 `b2c03d3`）。
   `extra="forbid"` 能阻止凭据字段进入 DTO，但 pydantic 默认消息会带上
   `input_value='...'`。实测 `Principal(..., password='hunter2')` 的
   `ValidationError` 文本包含 `hunter2`；把 `actor_id` 传成原始 Basic header
   字节串时，异常文本包含该 base64 凭据。适配器记录这条拒绝日志，就会导出
   该字段刚刚拒绝的机密，与 PRODUCT-CONSTRAINTS「Credentials and secret-bearing raw
   inputs must not enter prompts or exported traces」冲突。在共享 `DTO` 配置上加
   `hide_input_in_errors=True`；`type=extra_forbidden` 等类型标记保留，
   `tests/test_domain_contracts.py:568` 的既有断言不受影响。

另删除 `IntakeEnvelope` 中名为 `normalize_received_at` 却原样返回的空校验器
（提交 `0f70cc0`），避免读者误以为 `received_at` 已被归一化时区。`AwareDatetime`
本身已拒绝 naive 值，删除后行为不变。
