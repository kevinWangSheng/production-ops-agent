# 任务记录

任务记录遵循 [AGENTS.md 的任务记录与交接约定](../../AGENTS.md#任务记录与交接)。
本目录保存需要跨会话或交接的任务及实验记录。

## 使用方式

- 使用稳定文件名，例如 `2026-09-08-dev-environment.md`。
  同一任务持续更新原文件，完成后原地保留。
- ROADMAP 链接当前任务，详细执行进展在任务记录中维护。
  简单修改无需建档，不适用的字段可以省略。
- 开始前填写目标、依据、前提、完成条件和下一步；
  执行后更新进展与证据。已有规范、计划和实验合同直接引用，不复制。
- 状态使用：待开始、进行中、阻塞、已完成、已取消。
  完成表示本任务的完成条件已满足；实验结论另记通过、失败或证据不足，
  不与任务状态混为一谈。

## 模板

```markdown
# <任务名称>

- 状态：待开始
- 更新日期：YYYY-MM-DD
- 依据：<相关计划、设计条款或验收要求的链接；适用时标注功能 ID>
- 工作区：<分支与 worktree 路径，开始执行时填写>

## 目标与范围

<要解决的问题、本次交付和范围界限>

## 前提与完成条件

- 前提：<依赖、必要环境、适用授权依据及缺失项>
- 完成条件：<可观察的结果、所需检查或审查；引用已有合同>

## 必要上下文

<相关文件、章节或参考实现的链接及用途>

## 执行进展与证据

<当前已完成和进行中的事项；重要失败与处置>

<每项验证记录：检查对象与版本、实际命令或步骤、
预期与实际结果、结论及证据位置；尚未执行的明确标注>

## 下一步与交接

<下一项具体动作；阻塞原因及解除条件；尚未验证事项>

<适用时记录运行中进程或服务及资源归属、未提交工作、
合并与 worktree 清理状态，以及清理后仍可访问的证据位置>
```

## 实验任务

实验执行前，在“前提与完成条件”中填写实验问题、版本、
步骤、预期结果、通过/失败判据、证据位置及失败处置；
已有实验合同直接链接。

执行结果记录在“执行进展与证据”。
