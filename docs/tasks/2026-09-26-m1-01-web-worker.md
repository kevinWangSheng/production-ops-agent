## 目标与范围

1. 工作台创建 Run 的三条路径（intake、`new_run`、超时续开）都写入真实驱动器要求的调查输入快照，构造方式与 `scripts/m1_live_runner.py` 同源。
2. 常驻 worker 命令：轮询可领取的 Run，先跑清扫（ADR-0005 决定 2），再经 `InvestigationRunner` + 持久事件日志驱动，页面按 #44 事件显示进度；多实例安全；SIGTERM 干净停止不丢工作；不打印秘密。
3. worker 组合接入 `DurableToolLedger`，工具次数/秒数跨重启持久。
4. 过期 Run 上的 `resume` 不再留死行。
5. `docs/development.md` 增加本地运行演示。

不做：验收入口改接（第 5 项）、投影修复、close/reopen、真实 OTel 工具源、新依赖。

## 决定与理由（Agent 自决，可逆）

1. **共享构造器放产品层 `opspilot/investigation/inputs.py`**（`ToolFace.input_for` 与 `continuation_input`），工具面（schema、证据上下文、变体）由组合根提供。理由：产品代码不能 import `scripts`/`tests`（架构测试），而 intake 发生在 web 进程，必须在产品层拿到工具面。
2. **fixture 工具面与执行器组合放产品层 `opspilot/tools/fixture.py`**，`python -m opspilot.web serve` 与 `python -m opspilot.worker_main` 都从这里取 `fixture_face()` / `fixture_versions()`。它是「工具 profile」：canned transport + 回显 scope 代际的控制快照，账本与证据落库走产品路径（`DurableToolLedger`、`DurableEvidenceStore`）。真实工具源换 transport/注册，不换执行器。`tests/m1_tool_support` 的同名 fixture 未改动（改它会波及大量既有用例，超出本项）。
3. **worker 入口 `opspilot/worker_main.py`**（`opspilot/worker.py` 已存在，`python -m opspilot.worker` 不可用）。`WorkerLoop` 只做 sweep → 列出 → 逐个 `runner.resume`；不协调实例，多实例安全完全来自 `claim()` 租约栅栏。SIGTERM：置 stop、不再 claim、有界 join 在跑的尝试（默认 30 秒），超时即退出——每一轮/工具结果都先提交再继续，租约最多 420 秒后过期，下一次 claim 从行恢复；不做「中途打断后停放」，那会把一个本可继续的 Run 交给人。
4. **`DurableStore.claimable_incidents`** 只读提示（queued，或 running 且租约已过期；未过期；事故开放），按 deadline 升序；权威仍是 `claim()`。
5. **过期 Run 上的 `resume` → `ILLEGAL_TRANSITION`**（与 #47「无续开参数的追问拒绝」同一处置）。理由：resume 不带新输入，过期的 Run 没有可恢复进去的东西；出路已存在——追问/纠正续开新 Run，或 cancel + new_run；只保留一条续开路径。未过期的停放 Run 上 resume 行为不变（重排队）。
6. 续开与 `new_run` 的输入都取 C3 续接（`continuation_input`：携带证据重绑新 run id、交接说明并入问题、新 deadline 进 scope_facts）；旧行无快照或无法续接时退回原问题的新输入，保证新 Run 一定可跑。
7. `bound_target_id` 与 `scope_facts.target_ids` 记 intake 的 target_id；fixture 只授权 `checkout-prod`，别的目标会在工具网关被拒绝为可见交接，不静默改写。
8. 工作台的 `run_versions` 从 `{"state": "v1"}` 改为 `fixture_versions()`（loop 的 revisions + 工具面修订）：web 与 worker 必须同一套，否则 claim 时 `blocked`。
