# r16 独立验收：歧义与不可定位窗口

依据仅为 `docs/tasks/2026-10-18-eval-pr-c-interface.md` 第 15 节及 R1–R10。
既有测试与 `eval_c_support.py` 仅用于学习公开 CLI、DTO 和离线假对象的用法；未读取实现源码或实现改动。所有测试通过 `main(argv, deps=...)`，不依赖内部轮驱动或私有中断状态。下列共 **12 条**，包含措辞歧义与缺少公开钩子的覆盖限制；没有用猜测的私有入口补齐。

## 1. 处理器调用与真实进程信号

- 原文：「收到 SIGINT/SIGTERM 时只做一件事，置位 `stop_requested`」「新增测试另行验证真实处理器的置位行为」。
- 读法 A：必须使用 `os.kill` 验证内核信号投递；读法 B：可同步调用 CLI 安装的真实处理器，验证同一置位/抛出语义。
- 测试采用 B：经 `signal.getsignal` 调用安装好的处理器，不替换它、不直接抛异常模拟信号。额外保留 R7 的直接异常兼容测试。未验证内核调度延迟。

## 2. 检查点所属模块与保护上下文

- 原文：「检查点函数为 `checkpoint()`」「在受保护段内调用 checkpoint 是合法的，但不起作用」「`_deferred_interrupts` 保留为兼容入口」。
- 读法 A：这些名字是可以直接导入的公开 API；读法 B：它们描述机制，尚未给出模块、签名、调用作用域与安装方式。
- 测试采用 B：通过信号后接缝返回、后续调查未启动及槽位 `not_started` 验证检查点，不猜导入路径。无法直接测试嵌套深度、不消费标志、保护段内手动调用 checkpoint 或退出保护段不补抛的每个微窗口；收尾仍为 130 是持久停止状态的外部检验。

## 3. R5 真实 sleep 的入口与计时

- 原文：「真实 `Clock.sleep` 必须在置位后尽快返回，延迟不超过 1 秒」「非保护段按 monotonic 截止时间做 ≤1 秒的分片睡眠」「假时钟的语义不变」。
- 读法 A：`Clock` 是已暴露且可独立构造的真实时钟类型；读法 B：它是机制名称，只有注入的时钟协议，没有真实类型的导入路径、构造和与停止状态绑定的方式。
- 测试采用 B：不自行实现一个会响应信号的时钟来冒充产品验证。新增测试在恢复洗净的假时钟 sleep 中发送一次/两次信号，检查完整 300 秒截止；**真实时钟的 ≤1 秒返回及保护段真实睡到截止时间尚未验证**，需要公开真实时钟及其绑定方式。

## 4. “段内不执行检查点”与 R4 的关系

- 原文：「段内既不 raise，也不执行检查点」；R4：「在受保护段内调用 checkpoint 是合法的，但不起作用」。
- 读法 A：保护段禁止调用 checkpoint；读法 B：允许调用，但不能因停止标志抛出。
- 测试采用 B，以 R4 的具体裁决解释：只断言处理器返回与收尾完成，不检查内部调用次数。

## 5. R6 传播确认边界

- 原文：「fault 记录必须在等待 flagd 传播之前写入 attempt 状态」「传播尚未确认时，`effective_at` 保持为空」。
- 读法 A：首个 resolver 返回即足以赋值，即使其内部刚收到停止请求；读法 B：resolver 返回后的检查点先响应停止，未完成传播确认则不能赋值。
- 测试采用 B：首次注入后 resolver 内发送信号，再返回正常值；R1 要求调用后检查点，最终 fault 非空且 effective_at 为空。错误分支在同一位置抛 LabError。只检查最终 lifecycle/probe 的 fault，不读取内部 attempt 对象；run 用单槽位，避免假设普通传播错误必须阻止下一次独立尝试。

## 6. R2 第二次信号的允许位置

- 原文：「第 2 次及以后的信号只在允许强制中断的位置 raise」「外部命令执行期间不强制 raise」。
- 读法 A：所有非保护段都允许强制抛出；读法 B：非保护段仍有在途外部命令例外。
- 测试采用 B：假 Investigator 的普通回调内第 2 次 SIGINT 或 SIGTERM 必须立即中断；注入、恢复、洗净、PG stop 内两次信号都须返回。没有公开外部命令执行器接缝，离线测试封禁 Popen，因此未覆盖在途命令的第二信号、超时与完成后检查点；没有通过运行 kind/PG 补测。

## 7. 文件写出与原子发布

- 原文：「closure 之后的冻结与证据写入：summary、journal、recording 封存、aggregate、lifecycle、probe.json、recovery 记录、`structural-replay.json`」。
- 读法 A：在最终文件路径打开写入代表写出；读法 B：临时文件封存后向最终路径原子发布也属于整段。
- 测试采用 B：透明拦截 Path.open 写入及 os.replace/rename/link 的公开目的路径，不假设临时文件名或私有 writer。summary/aggregate/lifecycle 在单槽位轮中发送信号，避免把轮末中断误解为必须撤销已完成槽位。若换用未覆盖的 I/O 机制导致钩子未命中，属于测试适配限制，不能直接归为产品违约。其余列举文件未提供专用封存钩子；probe/recover 测试验证恢复中断后文件确实写出，**没有定位每一种文件各自写入的中途**。

## 8. marker 与 occupation 的完整转换

- 原文：「占用与 active marker 的创建和删除，以及 occupation release」「marker 只保护创建和删除，不跨越它的 yield」「occupation 在获取锁之前仍可中断」。
- 读法 A：occupation release 是删除 reservation 文件；读法 B：释放本次持有的资源/锁，不意味着删除外部占用声明。
- 测试采用 B，沿用公开夹具中保留 reservation 的外部约定。在实际 unlink 删除意图/active marker 后、调用返回前发信号，验证最窄的删除后窗口。未暴露 marker 创建事务与 occupation release 的公开钩子；未定位它们的中途。flock 重试前检查点与阻塞占用等待也没有此轮可注入的公开接缝。

## 9. R1/R8 在途调用与录制

- 原文：「每个服务的 HTTP 子请求、每次 DB 操作与迁移、余额读取、项目准备、trace flush 与 read-back、逐录制核验」「已完成的物理调用先记录，再做检查点」。
- 读法 A：整个 Investigator 接缝的一次返回足以代表所有物理调用；读法 B：各物理调用都需独立边界，不能从粗粒度返回推断。
- 测试采用 B：只声明覆盖可注入的余额、telemetry spans 与 Investigator 回调检查点。支持夹具不暴露真实 DB/迁移、模型/工具代理、项目准备、flush/read-back、逐录制核验的子调用钩子，不能声称这些位置已逐一验证；record(drive) 内部也不通过改实现定位。

## 10. R9 PG 启动失败清理与 closure stop

- 原文：「`LocalPgLauncher.start` 的失败清理、closure 中的 stop 及其重试」「closure_reason 记 `PG_STOP_FAILED`」。
- 读法 A：替换 Pg.start 抛错误即可验证真实 launcher 的内部失败清理；读法 B：这只模拟 start 已失败，不能验证真实清理范围。
- 测试采用 B：在公开 Pg.stop 假对象中发送信号并抛 PG_STOP_FAILED，检查 130、closure_reason、恢复及后续槽位。stop 允许重试但不猜重试次数。**真实 LocalPgLauncher.start 内部失败清理未覆盖**，需公开命令/清理注入钩子，不能启动真实 PG 来补齐。

## 11. R10 快照的最晚可观察边界

- 原文：「进入最终输出前先取快照」「快照之后到达的信号不再改变结果」。
- 读法 A：取快照到序列化之间有可用公开钩子；读法 B：最早可确定处于快照之后的位置是 stdout.write 收到完整 JSON 时。
- 测试采用 B：在 stdout.write 收到 JSON、实际写出前，调用此次 CLI 安装的真实处理器；断言 JSON 的码与返回码一致且仍为 0。处理器从 Investigator 回调捕获，避免假设输出时是否已经恢复原处理器。无法细分“快照后、JSON 序列化前”的窗口。预检另测无信号拒绝为 3、预检内信号为 130；未暴露先到顺序时间钩子，未覆盖开始后 3 与 130 的全部同级排列。

## 12. 信号与假对象主动异常

- 原文：「受保护段不屏蔽它」「假对象主动抛出的 `Interrupted` 或异常属于接缝故障注入」。
- 读法 A：假对象中调用真实处理器导致旧实现抛 Interrupted，也属于主动异常，不能要求保护；读法 B：主动 raise 与调用安装好的真实处理器应区分，后者必须遵守 r16。
- 测试采用 B：保护测试中的假对象自身不 raise Interrupted；处理器必须正常返回，随后假对象继续执行。另以专门用例直接 raise Interrupted/KeyboardInterrupt 验证兼容路径，不用它们替代真实信号测试。
