# M1-01 子任务「安全与验收」

## 目标与范围

在 `feature/m1-01-acceptance` 建立外部 `IncidentScenario -> IncidentOutcome`
薄组合层，组合调查 loop 的只读执行结果、DurableStore/worker 的业务状态与
人工控制结果；不重写工具执行器、调查 loop、持久化或恢复模块。验收入口只暴露
证据 ID、决定、动作、权限、人工交互、handoff 原因和最终状态。

- `AGENTS.md`「验证与汇报」「独立审查与上下文交接」；
  `SPEC.md` 当前 bounded-open M1-01、Operating constraints、Verification and delivery；
  `PRODUCT-CONSTRAINTS.md` 全文。

  `docs/testing/first-investigation-v4-2026-09-10.md`；C3 第 5、7、8、12 节。
- 起点为 `integration/m1-01`，依赖 PR #20、#26、#28、#29、#30 的已合入集成结果。

  DeepSeek ledger 记录做入口投影，未新增付费调用。

## 完成条件

- 每个本任务场景有确定性测试和逐步骤结果表：正常/故障报告、预算与 deadline
  拒绝、人工 pause/cancel、迟到结果拒绝、worker 重启续跑、不兼容状态 blocked。
- PRODUCT-CONSTRAINTS 六组约束有明确确定性断言清单；秘密扫描接入 acceptance 目标。
- 至少一个真实 DeepSeek Run 的 ledger 记录通过同一外部投影入口；不把 handoff 当正向能力通过。
- `make check` 通过；不修改 feature steps/passes，不宣称产品验收通过。
