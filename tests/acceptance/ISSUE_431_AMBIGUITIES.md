# Issue #431 acceptance ambiguities

- GitHub issue/comment retrieval was unavailable in this environment (`gh issue view 431 --comments` returned `Post "https://api.github.com/graphql": EOF`). The tests therefore use the checked-in seams handoff and closure contract as the authority.
- The handoff names `validate_injectors`, `ModelTransportFault`, request/intake helpers, and v2 storage behavior, but does not specify the exact public module/function names for `InjectorHarness`, `build_alertmanager_request`, `write_intake`, `validate_recorded_model_error`, `validate_round_bindings`, or v2 storage round-trip helpers. Tests resolve these names dynamically so collection succeeds; implementation should either expose these names or the acceptance contract must name replacements.
- The exact fake dependency constructor and interruption hook for exercising a crash between effect and wash are unspecified. The test requires an observable durable `fault-active.json`, per-injector phases, and deterministic recovery; the harness may provide an equivalent public fake.
- The exact recording fixture API for a model HTTP 503 is unspecified. The assertion fixes the seams contract (complete JSON body, matching `Content-Length`, parent `MODEL_UNAVAILABLE`, no response reference) without assuming a private recorder call sequence.
- The issue brief's “only lab webhook token” rule does not state whether the public request builder returns raw bytes or a decoded mapping. The test currently uses the mapping shape described in seams §5; expose an equivalent shape if the transport wrapper is bytes-oriented.
- PG-dependent intake counts are represented as offline artifact validation here. A separate PG-gated test may add end-to-end counts once the public app/temporary-database fixture is exposed; no cluster, network, or model is used by this file.
