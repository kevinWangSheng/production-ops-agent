## 目标与范围

调查能对一个配置好的 Redis 或 Valkey 单节点只读查看：INFO、CONFIG GET、SCAN 键名、单键元数据、按类型读值、慢日志。工具只进扩展档位 `otel-demo-ext`，只有设了 `OPSPILOT_REDIS_URL` 时才出现；未设时所有现有 revision 字节不变。本 PR 不接 SREGym 与 holmes_evals。

## 合同（r1，lead 预审 2026-11-22）

- U1=c：只交产品工具，不接评测；用户名与口令必填。
- U2=a：账号自查同 C6-U1：只读账号授予 `+acl|whoami +acl|getuser`；工具只读自己的用户，从不返回 GETUSER 应答，拒绝说明只点名违规规则。
- R1 六个工具，命令固定、无自由命令参数：`redis_info`、`redis_config_get`、`redis_scan_keys`、`redis_key_info`、`redis_get_value`、`redis_slowlog`；模型只给 sections、glob 模式、键名、类型过滤与 limit。
- R2 线上命令：握手 `AUTH user pass`、`CLIENT SETNAME opspilot-redis-tool`、`SELECT <db>`（db≠0 时）、`ACL WHOAMI`、`ACL GETUSER <self>`；`INFO [sections]`（7 以前每段一次）；`CONFIG GET`；`SCAN cursor MATCH m COUNT 1000 [TYPE t]`；`TYPE`/`PTTL`/`OBJECT ENCODING`/`MEMORY USAGE` 加一个长度命令；字符串 `GETRANGE 0 8191`（不用 GET）、哈希 `HSCAN`（不用 HGETALL）、列表 `LRANGE 0 limit`、集合 `SSCAN`（不用 SMEMBERS）、有序集合 `ZRANGE 0 limit WITHSCORES`、流 `XREVRANGE + - COUNT limit+1`；`SLOWLOG GET n`。
- R3 冻结的命令/子命令白名单，在唯一的 `_send(argv)` 里写字节前断言；两层：账号自查 + 命令表。合同所列禁止命令一律不发。
- R4 账号自查：无 `allcommands` 标志、无 selector、每个 `+` 规则是 `+@read` 或 R2 命令；其他 `+@类别` 与读不懂的应答 fail-closed。码 `REDIS_ACCOUNT_NOT_READ_ONLY`、`REDIS_ACCOUNT_UNSUPPORTED`（没有 ACL 或只有 requirepass），都归 SOURCE_FORBIDDEN；拒绝后不发工具命令。模块级 `account_problem(getuser_reply)`。实验/CI 授权见下「CI」。
- R5 不支持集群与 Sentinel；MOVED/ASK → `INVALID_PARAMS`（`REDIS_CLUSTER_UNSUPPORTED`）。
- R6 `OPSPILOT_REDIS_TLS` = `verify-full`（默认）、`require`、`disable`；`OPSPILOT_REDIS_CA_FILE` 须可读，`disable` 时不许设；只接受 `redis://`。
- R7 每次调用总计 30 s；连接超时 min(剩余−2 s, 10 s)，至少 1 s；看门狗到期关 socket → `TOOL_TIMEOUT`；每次新连接、不建池、不重试；SCAN 最多 50 轮，超出标不完整。
- R8 `limit` 默认 100、1–500；慢日志 1–128、默认 50；原始读取超 2 MiB 或视图超 25k token 整条 `RESULT_TOO_LARGE`；字符串截 2000 字符并列入 `_truncated_fields`；非 UTF-8 显示为 `0x` 十六进制；配置最多 500 行。
- R9 脱敏：CONFIG GET 工具侧拒绝表恒显示 `[REDACTED_CREDENTIAL]`（含空值）：`requirepass`、`masterauth`、`masteruser`、`tls-*-pass`、名字含 pass/auth/secret、共享规则判为凭据名的；哈希按 `{field: value}` 返回由共享脱敏处理；凭据名键下的字符串值替换；慢日志 `AUTH`、`HELLO`、`MIGRATE`、`ACL` 之后的参数替换；`may_contain_secrets=True`；不扩共享 `_credential_name`。
- R10 配置：`OPSPILOT_REDIS_URL=redis://host[:port]`，userinfo、路径、查询串、多主机 → `REDIS_CONFIG_INVALID`；`OPSPILOT_REDIS_DATABASE` 整数默认 0，模型不能选；`_USERNAME`、`_PASSWORD` 必填（`REDIS_CONFIG_MISSING`）；没设地址却设了其他 `OPSPILOT_REDIS_*` → `REDIS_CONFIG_INVALID`；web 只读地址；启动码进 `profiles._STARTUP_CODES`；lab 闸门 `REDIS_NOT_LAB`；指向 OpsPilot 自己 `OPSPILOT_*DSN` 主机端口 → `REDIS_TARGETS_OPSPILOT_DB`；入口脚本放行 `OPSPILOT_REDIS_*`，凭据槽 `redis-ro`。
- R11 工具名 `redis_*`，描述写「Redis or Valkey」、不承诺写模式；接在 MongoDB 之后，`tool_schema_revision(..., redis=False)`、`REDIS_TOOL_SCHEMA_REVISION`、`REDIS_TOOL_NAMES`；未设地址时现有 revision 字节不变；调查提示词不变。
- R12 `result_path=("results",)`、`source="otel-demo"`、selector `redis_endpoint`（不含凭据）、verb `get`；行单位 sections、parameters、keys、fields、elements、entries。
- R13 查询时刻的现状读取，无源时间；notes 写 read at query time；无 start/end 参数；慢日志时间转 ISO 8601 UTC。
- R14 错误：拒连、DNS、TLS、期限前断开、`-LOADING`、`-BUSY` → SOURCE_UNAVAILABLE；`-NOAUTH` → `REDIS_AUTH_REQUIRED`、`-WRONGPASS` → `REDIS_AUTH_FAILED`、`-NOPERM` → `REDIS_FORBIDDEN`，都归 SOURCE_FORBIDDEN，只显示码、不回显服务器文本；坏输入 `INVALID_PARAMS`/`INVALID_IDENTIFIER`，键与模式 1–1024 个可打印字符；键不存在 → `no_data`，note `KEY_NOT_FOUND`；其余 SOURCE_ERROR。
- R15 标准库 RESP2 客户端（socket、ssl），`RedisTransport(config, *, connector=None, request_timeout_seconds=30.0)`，不加依赖。
- R17 CI：`db-backends` job 加按 digest 钉住、绑 127.0.0.1 的 Valkey 9.0.x 容器，低熵测试管理口令，`OPSPILOT_DB_BACKENDS=1` 门控。
- R18 三个新变异：去掉 CONFIG 拒绝表、去掉 `_send` 白名单断言、`account_problem` 恒返回 None。

## 实现决定（实现者自定，可逆，2026-11-22）

- 账号自查放行的 `+` 规则 = `+@read` ∪ R2 命令 ∪ 合同实验授权里另有的 `+ping`、`+hello`、`+slowlog|len`（R4 原文只写「R2 命令」，但同条的实验授权含这三项且验收要求该授权通过；三者是无害读，且只放行账号检查，不进线上白名单）。
- GETUSER 应答缺 `selectors` 字段（Redis 6 没有 selector）视为「无 selector」并据此判定为 7 以前的服务器（INFO 每段一次），不另发版本查询；字段存在则必须是空列表。`flags` 须为列表、`commands` 须为非空字符串，否则 fail-closed。
- 工具读的是 `ACL WHOAMI` 返回的名字（须为 1–1024 可打印、无空白），不是配置里的用户名。
- 参数名（与测试作者对齐）：`redis_info.sections`（逗号分隔，取值 server、clients、memory、persistence、stats、replication、cpu、modules、errorstats、cluster、keyspace、commandstats、latencystats；缺省发不带参数的 `INFO`）；`redis_config_get.pattern`（单个 glob，缺省 `*`）；`redis_scan_keys.pattern`（缺省 `*`，总带 MATCH）、`type`（string/list/set/zset/hash/stream）、`limit`；`redis_key_info.key`；`redis_get_value.key`、`limit`；`redis_slowlog.limit`。
- `redis_get_value` 先发 `TYPE`（R2 里已有）再按类型读；字符串行单位用 `elements`（合同未列）；读满 8192 字节的字符串同样列入 `_truncated_fields`（可能更长）；未知类型（模块类型）→ `REDIS_TYPE_UNSUPPORTED`，归 INVALID_PARAMS。
- `HSCAN`/`SSCAN` 用 `COUNT limit+1`，与其他集合读一致；同样最多 50 轮。慢日志发 `SLOWLOG GET limit+1` 判断截断；脱敏从第一个 AUTH/HELLO/MIGRATE/ACL 词之后的全部参数。
- URL 允许一个末尾 `/`（同 C6c Mongo 先例），`/0` 之类路径拒；`OPSPILOT_REDIS_DATABASE` 只收十进制 0–2^31−1；没设地址时任何非空的 `OPSPILOT_REDIS_*` 都报 `REDIS_CONFIG_INVALID`。
- 默认连接器 `getaddrinfo` 后 `socket.settimeout(连接超时)` 再 `connect`（与测试作者对齐）；连上后读超时 30 s 只作兜底，到期由看门狗 `shutdown`+`close`。连接器第二个参数就是连接超时（≤10 s）。
- `_send(self, argv)` 是模块内唯一一个类 `_Wire`（包一次调用的连接）的实例方法，按合同写法 `_send(argv)`；最初写成 `RedisTransport` 的静态方法 `_send(conn, argv)` 时，独立安全测试的探针对它无效，M44 存活，改后被杀。
- `REDIS_NOT_LAB` 由 `tracing.check_lab_target` 产生（同 `MONGODB_NOT_LAB`），也列入 `_STARTUP_CODES`。
- revision：仅 Redis `otel-demo-ext-4b6894cef538`；无后端 `c63f058afb18`、MongoDB `f3c82122dcd8` 等现有值不变（本分支实测，既有钉值测试全过）。

## 数据源登记（PRODUCT-CONSTRAINTS 数据流）

新只读数据源 Redis/Valkey，仅 synthetic lab：返回 INFO 字段、配置（凭据类参数恒脱敏）、键名、单键元数据、键值（字符串前 8 KiB、集合前 limit 项，值截 2000 字符）、慢日志（含其他客户端的命令参数与地址，AUTH 等参数脱敏）。去向同其他工具：证据存储与所选模型；`may_contain_secrets=True`，共享名称脱敏之外，无名字上下文的裸密钥识别不了（残余风险，同 C6）。

残余风险：实验授权的 `+acl|getuser` 允许该账号读任何用户的 ACL（含口令哈希），工具只读自己且从不返回应答，但账号本身有此权限；`+@read` 也包含 `GET`、`KEYS`、`DUMP` 等，挡住它们的是命令表这一层（Valkey 9.0.1 实测）。
