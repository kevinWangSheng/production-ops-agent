状态：**C3 完整设计已通过独立全文对抗性审查，用户已审核正文并授权写入**。日期：2026-09-07。

本文是当前技术方案，替换此前提案中冲突的 checkpoint 恢复与资源部署设计。技术方向和领域合同已确定；依赖锁版本、模型兼容性、容量、费用和效果仍需 M0 及后续运行证据。设计通过不代表功能验收通过。实施入口条件见 [SPEC](../../SPEC.md#conditions-for-entering-implementation)，工作顺序见 [ROADMAP](../../ROADMAP.md)。

## 1. 目标与产品边界

构建能够持续运行的只读运维调查 Agent，支持两个入口：

- **事故调查**：从告警、异常或人工请求进入，结合实际上下文调查原因。
- **发布后观察与调查**：观察真实发布后的健康变化，发现异常后展开调查，并关联或创建事故。

两个入口复用同一套上下文驱动的调查机制。Agent 根据当前证据决定下一步查询，不按预设故障类别选择固定调查流程或专用 prompt。故障类别用于测试覆盖与结果分析。

首个完整版本包含证据采集、关联、调查和有依据的结论；人工追问、纠正、暂停、接管、取消、关闭与重新打开；人工整改后的独立恢复观察；复盘草稿、人工审核及版本化知识；持续运行、进程恢复、权限隔离、审计与可观测性；可复现的实验环境、eval、部署和运行验证。

Agent 不执行生产写操作，不拥有发布批准或阻断权。不纳入预发布通用代码审查、自动测试产品，以及独立的成本、安全、容量治理 Agent。

## 2. 技术栈与复用方式

| 部分 | 当前方案 |
|---|---|
| 服务语言 | Python 3.12 |
| HTTP 与数据合同 | FastAPI、Pydantic |
| 页面与实时更新 | Jinja、少量 JavaScript、SSE |
| 调查循环 | LangGraph，作为待验证的编排底座 |
| 模型接入 | AsyncOpenAI 兼容客户端、薄 provider 适配层 |
| 首个模型服务 | DeepSeek 官方服务 |
| 持久化 | PostgreSQL、psycopg |
| Agent trace 与 eval | LangSmith |
| 服务运行观测 | OpenTelemetry、Prometheus、Grafana |
| 本地与实验部署 | Docker Compose、Helm，共用应用镜像 |

暂不增加 Redis、Kafka、Temporal，也不同时引入 OpenAI Agents SDK 的另一套循环。

**LangGraph 的职责限定为调查循环编排。**它的 checkpoint 可以作为尝试内的可重建缓存，但不拥有跨进程恢复权威。跨进程恢复以 PostgreSQL 中已提交的业务记录为准。

由于这一职责比最初选型设想更小，M0 需要检查 LangGraph 是否仍能减少实现与维护成本。若没有净收益，再调整底座；不能为了保留框架降低恢复要求。

复用方式：

- 参考或移植 HolmesGPT、OpenSRE 的调查循环、上下文、知识加载、工具组织和任务租约设计，不照搬其默认 shell、写权限、存储耦合或外围平台。
- 参考 Pi 的 provider 适配设计、K8sGPT 的适用分析器，不因此增加另一套运行时。
- 优先使用现成的只读 API 客户端、eval SDK 和实验环境。
- Incident、Run、人工控制、证据采纳和恢复观察合同由本项目明确维护。

依赖组合尚未形成经过运行验证的锁定版本清单。依据与替代条件见 [运行底座比较](../research/runtime-selection-2026-09-07.md)、[eval 平台比较](../research/eval-platform-selection-2026-09-07.md)、[上游源码比较](../research/investigation-source-comparison-2026-09-07.md)。

## 3. 运行角色与权限

系统采用同一应用镜像的不同运行角色，权限分别配置。

| 角色 | 职责与权限 |
|---|---|
| Controller | 唯一业务写入口，处理接收、任务领取、续租、控制、证据与结果提交 |
| Worker | 执行调查循环；无被调查系统凭据，不向模型提供任意代码或数据库写工具 |
| Tool Gateway | 持有目标范围内的只读凭据，独立校验查询授权、预算和结果提交 |
| Observer | 执行独立、确定性的健康观察，不由调查模型认证恢复 |
| Exporter | 消费导出任务，发送允许的 trace 和 eval 数据，无结论修改权限 |

隔离必须落实到凭据、数据库权限和网络可达性。仅拆成不同进程，不算完成权限隔离。

Worker 的业务变更通过 Controller 提交。框架缓存如需独立存储权限，只授予缓存范围的最小权限。

## 4. 核心数据与生命周期

主要持久对象包括：

- `Integration / Target`：接入信息及不可变目标身份。
- `InputEvent`：来源事件、投递去重信息和接收时间。
- `Incident`：事故生命周期、人工控制版本、当前调查 Run。
- `ReleaseObservation`：发布身份、目标、发布版本、观察状态及关联事故。
- `Run`：所属主体、执行状态、模型配置、累计预算、输入水位和执行 epoch。
- `ModelStep`：稳定步骤 ID、输入快照、完整模型响应及工具计划。
- `ToolOperation / Evidence`：操作身份、查询范围、时间窗、结果和采纳状态。
- `Job / Schedule`：到期时间、调度版本、租约和唯一执行键。
- `ObservationSession`：观察主体、授权、健康规则版本和已采纳采样水位。
- 主体事件、审计记录、导出 outbox。
- `Postmortem / KnowledgeRevision`：复盘与不可变知识版本。

### 事故与发布观察分开建模

事故生命周期：`open → observing_recovery → resolved → closed`，支持人工重新打开。人工关闭不等于系统独立确认恢复。

发布观察状态：`pending / observing / healthy / anomalous / unknown / cancelled`，后四种为终态。正常发布拥有独立观察记录，**不需要先创建一个事故**。发现异常后，再创建或关联 Incident。

发布身份使用来源唯一发布 ID、目标和不可变发布版本。重复投递去重；新发布版本建立新记录。暂停保留状态并停止调度，恢复仍受原总 deadline 约束；终态再次观察创建关联的新记录。

### 调查状态与调查结果分开

Run 状态包括 `queued / running / waiting_human / paused / blocked / completed / failed / cancelled / budget_exhausted`；调查结果单独表达为 `supported / inconclusive / partial`。

执行完成不自动代表原因找对，也不代表已经恢复。

### 人工控制与结果所有权

- 人工操作使用 `expected_version` 条件更新，并增加对应主体的 `control_generation`。
- Run 显式绑定主体类型和 ID，每个主体只有一个当前 Run 可以更新该主体的调查结论。发布 Run 不得跨主体修改 Incident 结论。
- 旧 Run 的迟到结果只能保存为历史，不能覆盖当前结论。
- 暂停期间继续接收事件，但不发起自动查询。恢复暂停的 Run 使用新的执行尝试。
- 取消 Run 后，该 Run 保持终态；继续调查创建新 Run。取消 Run 不等于关闭 Incident。
- 已关闭事故遇到新异常，默认创建关联的新事故；人工也可显式重新打开。
- 目标重新绑定、事故合并或拆分，需要在事务中撤销受影响的旧调查和观察授权，保留历史证据身份。

每轮调查固定实际处理的输入水位。新追问和新事件在安全边界纳入，不能把尚未分析的输入显示为已处理。

### 全局与目标级暂停

全局及服务级 suspension 属于确定性控制状态；服务范围解析为登记的不可变目标集合，不能以模型提供的名称决定。全局暂停或目标暂停任一生效时，都优先于主体 resume、automatic 模式及 human_owned 下的单独观察授权；涵盖调查工具查询、Observer 采样和新的调查模型调用，不禁止接收事件、查看历史或记录人工操作。

暂停事务增加对应 scope generation。任务领取、模型预算预留、网关发起请求及结果采纳均校验当前全局/目标控制版本；暂停使相关在途结果失效，仅保留历史，按既有有界取消规则清理，不能承诺撤销已经发出的请求。授权检查不可用时停止新调用。

解除暂停只移除该层阻挡，不自动恢复旧任务、旧观察授权或采样窗口。受影响主体需显式恢复/重新授权；新尝试使用当前所有控制版本，其他 scope 的暂停及主体终态仍有效。事件继续持久接收，原 deadline 和累计预算不重置；已过期 Run 使用新 Run 接续，暂停期间事件不得显示为已分析。

## 5. 模型适配、上下文与调查循环

### 模型接入

2026-09-09 用户决定默认使用 Flash；当前配置为 DeepSeek 官方 Chat Completions 兼容接口、`deepseek-v4-flash`、thinking 开启和 high effort，直接请求 Flash，不依赖 Pro 别名转路由。此前 Pro 实验作为历史证据保留，不替代 Flash 验证。2026-09-09 新 Flash 固定工具/严格 JSON/PG/白名单 trace 链路已单次通过，真实调查基线另见[本轮证据](../tasks/2026-09-09-m0-real-investigation.md)；不代表全部协议/恢复矩阵或产品验收。记录请求模型名、可获得的响应版本信息、调用日期和依赖锁版本。完整协议/恢复兼容矩阵仍需实验，单次链路通过不代表该矩阵通过。

使用 OpenAI 兼容客户端不意味着使用 OpenAI 模型服务，也不意味着采用 OpenAI Agents SDK。

适配层负责接口地址和认证、请求参数及能力差异、工具调用与流式响应归一化、必要协议字段的保存和续传、错误分类、超时、重试和用量记录。

业务 prompt 尽量共享。只有实验显示确有必要时，才增加模型专属 prompt 调整。接入 GLM 等其他 provider 时，通过新 Run 继承允许迁移的业务事实，不直接迁移旧 provider 的私有协议历史。

选择薄适配器的依据是核查版本的 ChatDeepSeek 接收端保留 `reasoning_content`，出站转换却遗漏该字段；避免依赖私有方法覆写，但需要维护并验证消息转换。该结论限定于审计版本，不表示未来上游版本必然有同一缺口。见 [适配源码证据](../research/deepseek-adapter-design-evidence-2026-09-07.md)、[模型适配与设计职责](../research/model-adaptation-and-design-ownership-2026-09-07.md)。

### 上下文

输入快照固定已纳入的事件、人工请求与纠正水位，上下文片段和压缩版本，模型、prompt、工具及知识版本，以及重建输入所需的实际内容或固定持久引用。

恢复先重建已提交步骤，再在明确边界纳入新输入。取消和权限收紧即时生效，不受旧快照覆盖。

知识检索仅使用经过审核的版本，初期使用 PostgreSQL 全文检索、名称和标签匹配。测试故障类别不决定加载哪套 prompt 或 skill。

大结果保存为持久证据，通过 ID 和片段读取；截断和不完整必须显式标记。上下文压缩保持完整消息组和工具调用配对。

DeepSeek 的 `reasoning_content` 仅作为受限协议状态保存，并在同 provider、同 Run 必要续传，不作为证据、复盘内容或评分对象。压缩或恢复后续传不兼容时，阻塞并交接，不猜测删除协议字段。

### 调查循环

`组装上下文 → 调用模型 → 提交完整响应和工具计划 → 执行并提交工具观察 → 下一轮`

- 流式响应完整且校验通过后，才允许执行工具。
- 每个工具调用必须有完整的结果或失败记录。
- 模型给出的最终文本先作为候选结论，校验证据引用、目标身份和当前采纳权后才能发布。
- 信息不足时允许明确给出无法确认或部分结论。
- 工具采用有限并行，不默认增加多个调查 Agent。

默认关闭 strict beta；400 类请求错误不盲目重试，429 和网络错误采用有界重试。

## 6. 事件接收、去重与持久调度

优先使用 `(source, external_event_id)` 去重。来源没有稳定事件 ID 时，使用来源实例、稳定对象身份、状态时间及规范化 payload hash 构造投递键。不能按资源名称永久去重，否则可能吞掉后续真实事故。

同一来源的事故 episode，可依据 fingerprint、开始时间及精确目标身份关联。跨来源信号默认建立相关关系，不直接强制合并。发布按第 4 节维护独立身份。

事件接收、主体建立、Run 或观察任务创建在同一事务中提交，提交成功后才确认接收。

任务调度：

- 使用短事务 `FOR UPDATE SKIP LOCKED` 领取到期任务，分配 owner、epoch 和 lease，网络调用在事务外执行。
- 续租和提交均校验执行身份与租约。
- 持久扫描过期租约，符合条件时重排并增加 epoch；终态任务或已失效调度版本不得重新执行。
- 重试耗尽后进入明确的阻塞或失败状态，保留人工接续入口。
- 周期任务持久保存 `due_at`、`schedule_generation`，以 schedule/generation/due 构成唯一执行键。
- 修改或取消调度时，原子失效旧任务。

Outbox 用于外部导出，不替代数据库内部任务调度。标准机制及上游启发见 [状态协议设计输入](../research/state-protocol-design-input-2026-09-07.md)；业务关联和采纳规则属于本项目设计。

## 7. 故障恢复与提交一致性

**PostgreSQL 业务记录是唯一跨进程恢复依据。**

每次执行尝试创建新的 Graph 执行身份，不跨尝试恢复旧的 latest checkpoint 或 pending task。

模型调用前以 `run_id + context_segment + logical_round` 创建稳定步骤键并原子预留预算；完整模型响应与工具计划提交后，才能执行工具。工具操作 ID 由步骤 ID 和工具序号稳定生成。

| 断点 | 恢复行为 |
|---|---|
| 模型完整响应尚未提交 | 有界重试，保留未知费用占用 |
| 响应已提交，部分工具未完成 | 只处理尚未完成的工具操作 |
| 工具结果已经提交 | 复用为历史观察 |
| 工具结果齐全 | 重建下一步上下文 |
| 结论已生成，发布未确认 | 条件更新与幂等提交 |

每个工具操作保存成功、失败、取消或状态未知的记录，重建不得留下悬空 tool 配对。状态未知不能当作成功，需要明确重新查询或交接。证据提交成功后才允许消费。

外部只读请求成功但数据库提交失败时，恢复可能重复查询，因此不承诺外部查询 exactly-once。历史证据保留原观察时间；需要当前状态时，创建新的观察操作，不能把旧结果重新标成新证据。

调查结果提交校验所属主体与当前 Run、主体控制版本、owner、epoch 和有效 lease。观察结果采用第 10 节的独立规则，不能套用调查 Run 的采纳权。

撤权后，旧受限证据不得再进入新模型输入；无法安全重建时阻塞交接。数据库不可用时，不确认尚未持久化的输入，不发起新的未记录调用。框架缓存不能覆盖业务日志。

恢复遇到不兼容的模型协议、工具或状态版本时，进入 `blocked(INCOMPATIBLE_STATE)`。保留旧记录，通过显式迁移或基于业务事实的新 Run 接续，禁止静默换版本续跑。

升级采用停止领取、排空或暂停、兼容检查的流程。首版不建设多版本滚动运行平台。

## 8. 工具网关

工具注册合同包含名称、版本、参数 schema、数据源、精确目标、绝对查询时间窗、请求 deadline、结果大小上限、错误分类及不完整结果标记。

授权以 Controller 保存的真实身份和控制状态为准，不信任模型提供的权限字段。

初期不提供任意 shell、SQL 或代码执行。Kubernetes 仅开放必要的 get、list、watch、logs，不开放 exec 和写操作。

指标查询的目标隔离使用真实鉴权代理或独立实例，不能依赖简单拼接过滤条件。MCP 工具也必须遵守相同的权限、预算和提交规则，只启用必要 adapter。

同时设置 SDK 超时、网关总超时和输出大小上限。不合作的调用放入可终止子进程。

取消不能撤销已经到达数据源的只读请求，但必须阻止后续调用、拒绝失效结果更新业务状态，并在有界时间内完成清理。

## 9. 页面、认证与人工操作

提供事故列表与详情、发布观察列表与详情、调查过程/证据/结果展示、追问与纠正、暂停/恢复/接管/取消/关闭/重新打开、复盘及知识审核。发布观察提供暂停、恢复和取消，不提供发布批准或阻断操作。

变更接口使用幂等键、预期版本和操作者审计。SSE 使用主体的持久事件序号；浏览器断线不取消任务，游标过旧时重新加载主体快照。

初期部署采用 Caddy TLS、具名 Basic Auth 和哈希口令。API 仅允许通过可信代理访问，剥离伪造身份头；记录变更请求校验 CSRF/Origin。事件接收使用独立认证 token。

首版不建设企业 SSO 和多租户系统。需要扩展时另评现成 OIDC 方案，不自建身份平台。

## 10. 独立健康观察与复盘知识

### 健康规则

接入目标使用版本化 `HealthProfile`，定义必要信号和探针、计算方式、最低样本与有效流量、阈值、新鲜度、观察窗口、缺测及信息不足时的处理方式。

不要求所有目标都是 HTTP 服务。没有 HealthProfile 仍可调查，但不能声称完成独立恢复确认。恢复观察使用整改后的新数据，必要信号缺失不能判定健康。

### 观察主体与授权

观察会话明确绑定 `incident_recovery` 或 `release_observation`、对应主体及不可变目标、主体控制版本、观察 generation、HealthProfile revision 和明确观察授权。主体类型与引用必须有效，不用空 Incident 代替发布主体。

发布观察不依赖 Incident 存在。转入事故调查后使用新的事故授权，不复用发布观察的恢复权限。

暂停、接管、取消当前调查、关闭或结束主体、重新打开、停止观察、修改目标或规则时，在同一事务中增加相关版本并撤销旧观察任务。更换 Run 不默认继承旧观察授权。

automatic 模式且生命周期允许时才自动查询。接管默认停止自动观察；人工可在 human_owned 状态下单独授权观察，但该授权不恢复 Agent 自动调查。

恢复或重新打开不继承旧采样窗口。规则变化后，如仍获授权则创建新版本观察会话，否则保持停止。

### 采样与提交

每个观察会话最多一个活动采样任务。每次新采样有单调序号和绝对时间窗；同一任务的租约重试保持原逻辑序号。

提交时原子校验：

- 当前主体、授权和全部控制版本。
- 规则版本、目标、owner、epoch 和 lease。
- 当前模式及允许的生命周期。
- 采样序号大于已采纳序号，采样窗口结束时间不倒退。
- 返回结果属于当前逻辑采样，且完整记录成功、缺测、陈旧、超时或失败及来源。

上述是共同采纳条件；数据覆盖、新鲜度和最低样本是判定 healthy 的必要条件，不是保存 unknown 观察的前提。合法采样的 no-data/stale/错误可采纳为 unknown，记录已用次数并按原 deadline 有界继续或交接；不增加健康持续窗口，不将查询失败等同健康。无效身份、授权或水位的结果仍只作历史。

恢复结果仅可在 open/observing_recovery 下采纳；旧结果不能改写 closed/resolved。发布结果仅在 pending/observing 且未过原 deadline 时采纳；终态不能由旧结果重开。

失效结果只保留历史，不改变生命周期，也不安排后续任务。采纳结果、更新水位、状态转换及安排下一任务在同一事务完成。

恢复观察健康后转为 resolved，结束该会话；仍异常或无法确认时有界继续，达到期限后交接。新异常或人工 reopen 使用新的阶段和授权。

发布观察具有固定期限、次数和频率：

- 健康：仅在发布后最短跟踪跨度已覆盖、规定采样覆盖及健康窗口均满足时结束观察；此前的健康采样仍处于 observing。
- 异常：幂等创建或关联事故，记录关联并安排独立调查。
- 无法确认或到期：明确交接。

发布观察配置固定发布起点、最短跟踪跨度、采样频率、健康窗口、覆盖/缺口处理和原绝对 deadline；最早 healthy 终结时刻不得早于最短跟踪跨度末端，所需窗口不得超过 deadline。暂停不把漏掉的跨度视为已观察，不自动延长期限；到期仍缺证据则 unknown。跟踪期内“先健康后变坏”必须能检出；终态之后的新异常按事件接收合同进入事故流程，不宣称已结束的发布观察仍在监测。具体数值在 M0 开发校准后冻结。

消费发布观察结果、事故关联/创建和任务安排在同一幂等事务完成。关联已有事故不能覆盖其人工控制或正在进行的调查，只增加事件并在安全边界处理；已关闭事故遵守新异常新事故规则。

界面区分调查因果结论和观察健康结论。人工关闭、Run 完成、发布观察结束与独立恢复确认不能混用。

### 复盘与知识

复盘先生成草稿。只有人工审核后，才能生成不可变知识版本。知识支持 supersede 和 revoke，保存审计；平台评分和模型自评不能直接更新生产知识库。

## 11. 可观测性、eval 与数据保留

### 可观测性

PostgreSQL 保存业务和审计真相。LangSmith 接收通过白名单 DTO 导出的允许字段，不自动上传完整 Agent state。通过主体、Run、步骤、工具和版本 ID 关联调查轨迹。

业务事务与 outbox 同时提交；外部导出至少一次，使用幂等身份。Trace 积压允许有界丢弃并记录计数，不能因此丢弃核心事件或证据。

### Eval

每次实验固定知识快照、事故或发布主体初始状态、session、人工反馈、workload 数据、模型/prompt/工具/适配器/evaluator 版本、权限、预算及实验环境。

开发集与保留集隔离，知识积累不得污染重复实验或基线比较。coding agent 的代码/prompt 调优也受隔离约束；可见资料、候选冻结及泄漏处置遵循 [M0 eval 执行合同](../plans/m0-validation-plan-2026-09-07.md#coding-agent-参与时的评测隔离)。“审核知识积累是否改善效果”单独作为实验。

可诊断性依据 Agent 实际可见证据预先判断，不能直接使用故障注入器答案。主质量指标评价定位和因果判断是否正确、结论是否获得证据支持；信息不足集另评是否准确交接。失败和放弃必须进入对应分母。

速度或成本改进不能抵消重大质量退化。先使用开发实验校准，再冻结样本数、重复次数、统计方法、通过阈值与不可接受退化条件，随后运行候选评测。

此前讨论的 80%、90%、120 秒属于待校准候选值，不是最终 SLA。上游基线尽可能匹配模型、权限、工具与预算；无法匹配的差异作为实验因素披露。

### 保留与删除

初始保留策略：活跃调查和恢复所需资料持续保留；关闭后的原始资料默认 30 天；报告、审计和知识默认 90 天或归档；eval 证据独立归档。

活跃调查、知识引用和归档实验所依赖的资料需要固定保留。清理覆盖原始数据、缓存、provider history、摘要、outbox 和外部平台副本。删除依赖时撤销相关用途或保留墓碑，不能留下看似有效但实际失效的证据引用。

不建设硬盘损毁备份和灾备。

## 12. 真实实验环境、资源与数据出口

### 实验环境

首个工作负载采用固定版本的 OpenTelemetry Demo，建立实际接入清单：数据源 endpoint 与访问身份，目标及版本关联标签，日志/指标/调用链等实际可用数据，保留窗口与 HealthProfile，以及发布对比所需的流量和历史数据前提。

正常主实验先验证这些条件齐全。故意缺测作为独立实验，不能把环境没有装好当作缺测测试。发布实验变更应用镜像或配置，不使用整个 chart 重建代替应用发布。

第二工作负载作为迁移性验证候选，不自动扩大首版范围。

### 资源与预算

本机 16 GB 内存、约 45 GB 可用磁盘属于此前观察的机器条件，不代表可全部分配给实验，实施前复核。

本地开发，按需使用 Linux 实验环境；持续运行测试期间，将控制服务与被调查目标隔离。候选容量为控制侧 4 CPU / 8 GB、目标侧 8 CPU / 16 GB，先测容量再采购，不要求常驻两台服务器或部署 HA。Compose 与 Helm 共用应用镜像。

| 用途 | 初始规划额度 |
|---|---:|
| 基础设施 | 300 元 |
| DeepSeek 调查与实验 | 450 元 |
| Judge | 100 元 |
| 平台 | 50 元 |

1000 元是可调整的初始项目预算。这些是预算分配，不是费用预测或采购授权。实际支出前复核价格，需要增加支出时提交具体方案。此前 7 天约 $36 的云价格仅为不含全部成本的历史比较，不构成采购依据。

### 数据出口

- 获授权业务证据可以进入选定模型调查及隔离的 eval。
- Provider 私有协议字段只允许回传同 provider、同 Run 所需的续接请求。
- 报告、知识、LangSmith 和 judge 不接收这些私有字段。
- 凭据不得进入模型上下文、工具结果、报告或 trace；可信客户端可以在对应服务的认证通道使用必要凭据。
- 目标查询凭据与模型服务凭据分离。
- 既有用途授权不等于未来所有数据源的无限授权。

## 14. 实施与验证里程碑

这是一个完整版本的内部推进顺序。

**M0：技术兼容与实验前提验证。** 锁定依赖和模型 profile；验证 DeepSeek 多轮工具协议、持久重建、重试与取消；验证升级兼容、权限范围及实验容量；冻结 eval 协议；评估 LangGraph 的实际收益。退出依据是实际协议/恢复/失败工件与环境测量，不能用 mock 替代真实模型和持久化路径。

**M1：完整纵向链路。** 打通认证接入、持久任务、调查循环、证据、结果、人工处理记录、恢复观察、审核复盘及内部观测，形成从干净环境可重复的完整路径。失败能解释并可按合同重试或交接，不代表完整产品已验收。

**M2：完整产品生命周期。** 完成两个入口、人工操作、复盘知识、迟到事件、故障恢复及独立观察。覆盖 F2、F3、F6、F7、F11、F12、F13；以相关合同测试和验收证据退出。

**M3：效果与交付验收。** 完成上游基线、保留集评测、持续运行、升级、部署和交付文档。覆盖 F1、F8、F9、F14，并完成全部活动验收。

安全和可靠性从前面的里程碑开始实现，不推迟到最后补做。后续版本根据实际结果规划；详细工期在 M0 取得依据后估算。
