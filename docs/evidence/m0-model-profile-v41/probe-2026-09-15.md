# `deepseek-flash` 请求名真实验证（2026-09-15）

一次有界真实调用，用于确认切换后的请求名可用性与回报名。
由用户在本会话中明确授权执行；探针自带 Run deadline 120s、请求超时 60s、输出上限 64 tokens。
不含业务数据、不上传 trace、不打印密钥。

## 结果

| 项 | 值 |
|---|---|
| 请求名 | `deepseek-flash` |
| HTTP | **200** |
| 回报名 (`response.model`) | **`deepseek-flash`** |
| wall（首发到响应） | 0.94 s |
| finish_reason | `length` |
| prompt_tokens | 37（cache hit 0 / miss 37） |
| completion_tokens | 64（其中 `reasoning_tokens` **64**） |
| total_tokens | 101 |

端点 `https://api.deepseek.com/v1/chat/completions`；参数 `thinking={"type":"enabled"}`、
`reasoning_effort="high"`、`max_tokens=64`、`stream=false`。

## 判定

1. **`deepseek-flash` 可调用**，该账号 HTTP 200。
2. **回报名与请求名一致**，故 `MODEL_PROFILE["accepted_response_model"] = "deepseek-flash"`
   的精确匹配 fail-closed 正确，不会误拒真实响应。这是本次切换唯一先前未被证据定死的点。
3. **未观察到其它别名**：回报既不是 `deepseek-v4-flash` 也不是任何带代次的字符串，
   与官方定价页「legacy names … their requests are served by the DeepSeek-V4.1-Flash model」一致。
4. **`finish_reason=length` 且 64 completion tokens 全为 `reasoning_tokens`，正文为空。**
   thinking enabled/high 下 `max_tokens` 必须覆盖推理预算加正文，否则得到空正文。
   这复现了历史记录中的「length 空正文」现象，属参数配置问题而非模型故障。
