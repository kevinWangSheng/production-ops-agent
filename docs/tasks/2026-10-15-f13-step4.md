## 公开接口（实现与独立测试共同依据）

1. **检索**（R4、U4、U1、R2、R3）：`KnowledgeStore.knowledge_for_target(resource_uid: str, query_text: str, *, limit: int = 3, max_age_seconds: int) -> dict`。`resource_uid` 即 `IntakeRequest.target_id`。一个只读快照事务内：取 `clock_timestamp()` 作 `retrieved_at`；候选为来源事故（revision → postmortem → incident → `opspilot_targets.resource_uid`）属于该目标、视图状态为 `active` 的 revision；`age_seconds = floor(retrieved_at − observation_ended_at)`，`age_seconds > max_age_seconds` 为 `stale`，否则 `fresh`；排序：fresh 在前，其次 `ts_rank`（`simple` 配置，query 对 name、tags、content）降序，再 `approved_at` 新的在前，再 `entry_id`；取前 `limit` 条，全文不命中不过滤。返回值就是 `scope_facts.knowledge`：
   `{policy_version: "knowledge-hint-v1", status: "ok", retrieved_at, max_age_seconds, omitted_for_size, entries: [...]}`；每条 entry：`entry_id, revision, name, tags, content, content_sha256, source_incident_id, source_postmortem_id, source_version, approved_by, approved_at, observation_ended_at, age_seconds, freshness, truncated`。时间为 ISO 8601 字符串，UUID 为字符串。
   - `content`：revision 的规范 JSON 文本，其中顶层 `evidence_refs` 换成 `{"omitted": true, "count": n}`（R2，旧证据 ID 不进 prompt），再规范化；超过 4096 字节（UTF-8）截断并 `truncated: true`。`content_sha256` 是库内原 revision 的值。
   - 总量：`entries` 的规范 JSON 超过 12288 字节时，从排名最低的一条起丢弃，丢弃数记 `omitted_for_size`。理由：R1 未定总量超限的做法，丢低排名条目并计数最保守且可见。
2. **检索失败**（R5）：存储不可用不阻塞 intake，事实记 `status: "unavailable"`、`retrieved_at: null`、`entries: []`。
3. **输入 v5**（R1）：`opspilot.investigation.context` 新增 `INPUT_VERSION_KNOWLEDGE = "opspilot-investigation-input-v5"`、`KNOWLEDGE = "knowledge"`；`scope_facts` 含 `knowledge` 即为 v5（优先级高于 v4）。形状不合法为 `INPUT_INVALID`；v1–v4 照旧读取。
4. **模型可见形态**（U3、R6、U2）：`KNOWLEDGE_BOUNDARY` 常量（不可信线索、不是本 Run 证据、须用工具核对、当前证据优先、标签约定），计入 `prompt_revision`。`entries` 非空时，固定前缀在告警上下文之后、证据上下文之前多一条 user 消息：边界文字 + entries 的规范 JSON；`entries` 为空或 `unavailable` 时不发消息，只记录在快照。标签约定：claim 文本含 `[knowledge:<entry_id>@r<revision>]`；与证据一致写 `fact` 并引用本 Run 证据，被否定写 `rejected_hypothesis` 并引用本 Run 证据，未核对写 `hypothesis`。
5. **核对结果解析**（U8，PR-C 投影复用）：`opspilot.knowledge.hints.knowledge_checks(knowledge_fact, report) -> list[dict]`，每条提供的知识一项：`entry_id, revision, verdict, claim_kinds`；verdict：`consistent`（带标签的 `fact` 且有 evidence_ids）、`contradicted`（带标签的 `rejected_hypothesis` 且有 evidence_ids）、`unverified`（只有带标签的 `hypothesis`，或标签所在 claim 不满足前两条）、`conflicting`（同时出现 consistent 与 contradicted）、`untagged`（报告里没有该条标签）。报告缺失时为 `untagged`。运行时不因标签拒绝报告（R8）。
6. **Run 创建**（U5、R7）：`Workbench` 新增 `knowledge`（具 `knowledge_for_target` 的对象，`None` 关闭）与 `knowledge_max_age_seconds`（默认 2592000）。首个 Run（网页与告警）检索，query 为 intake 问题；后继 Run（new_run、续期、reopen）对原 intake 问题**重新检索**并替换上一 Run 的 `knowledge`。web 进程默认启用，`OPSPILOT_KNOWLEDGE_HINTS=off` 关闭，`OPSPILOT_KNOWLEDGE_MAX_AGE_SECONDS` 调阈值（实验环境调小以造陈旧知识）。脚本与评测走 `fixture_face().input_for`，不受影响。
7. **页面**（U8）：事故页 `id="knowledge-hints"` 段落：检索状态、`retrieved_at`、阈值；每条知识的条目链接（`/knowledge/<entry_id>`）与 revision、新鲜度、年龄、来源事故链接、截断标记、核对结果。

## 自定的可逆细节

- revision 内容没有 `evidence_refs` 时也写入 `{"omitted": true, "count": 0}`，让模型看到的形状一致。
- `stale` 判定用严格大于：年龄恰等于阈值仍算 fresh。理由：「超过阈值 N」的字面意思。
- 检索不在 `accept` 事务内，在 `_fresh_input` 中单独开快照事务；intake 重放以首次写入为准（`incidents.py:83-90`），重放时多做一次检索不改结果。
