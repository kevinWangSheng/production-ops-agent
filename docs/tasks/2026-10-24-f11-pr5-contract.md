## 4. 给独立验收测试作者的确定性行为清单（只用公开接口：HTTP 路由、`ReleaseStore` 公开方法、`Workbench` 的 pass、Observer `poll_once` 加测试构造的 Prometheus 响应、`replay_session`；PG 非 owner 角色）

**第 1 步：观察到的发布触发调查，保留精确前后版本与服务身份**
1. release-deployer `POST /intake/version-changes` → 201 created、发布 pending；一次自动授权 pass 后 → observing，恰 1 个 authorized 会话，审计 1 条 `authorize/applied`，principal `system`；再跑 pass → 无新审计、无新会话。
2. 同载荷重投 → 200 replayed，主体仍 1 个，不产生第二次授权或会话。
3. `GET /version-changes/{id}`（HTML 与 JSON）中前后版本每个 image digest、pod-template/config digest、目标五字段、`source_release_id`、`released_at` 与载荷**逐字节相等**。
4. 构造延迟回归采样 → anomalous → `release_anomaly_pass` 后：恰 1 个事故、1 个 Run，Run 输入 v6 的 `release_observation` 事实中的前后版本与目标身份与第 3 条相同，含新旧实例（pod UID）；详情页显示 link 与事故 id，事故页显示反向链接。
5. 自动授权不发生的情形（发布保持 pending，无会话，零 Prometheus 查询，拒绝原因在详情页可见）：全局或目标挂起（`SCOPE_SUSPENDED`）；清单不匹配（`RELEASE_POLICY_UNCALIBRATED`／`_MISMATCH`）；已过 deadline。挂起解除后再跑 pass → 仍不授权；到期后清扫 → unknown。
6. event token 访问三条新 GET／POST → 401；UI 用户 POST `/intake/version-changes` → 401/403。

**第 2 步：在审定的流量策略下比较发布前后、新旧实例；含健康发布与无关并发故障**
1. 详情页显示冻结 policy revision（审定的流量策略）与对比记录：before 窗起止等于合同值（`released_at − evaluation_window` 至 `released_at`），四个 scope 的状态与信号；采集失败显示 `unavailable`，不改变发布状态。
2. 健康发布：after 切片健康 → healthy，零事故、Run、link、事件。
3. 无关并发故障：其他服务（如 ad、frontend）错误上升、checkout 新版本切片健康 → healthy，不关联任何事故。
4. 版本映射或流量不足 → unknown，不输出 degraded（A5）。

**第 3 步：延迟回归被定时跟进发现，健康发布不被无休止重查**
1. 先若干健康采样、deadline 前出现合格 degraded 采样 → anomalous；重复 pass、并发两个 pass → 仍 1 个事故、1 个 Run。
2. 健康终态后：再跑 Observer `poll_once`、自动授权 pass、异常 pass 若干轮 → 该发布零新采样、零新会话、零审计、零事故；采样总数 ≤ 40；同载荷重投不重开。
3. 暂停期间零采样；HTTP resume 后新会话，健康／跟踪窗口不继承，deadline 不变；到期仍缺证据 → unknown。

**第 4 步：输出区分 healthy／degraded／unknown；不改变任何 CI 检查、部署门、rollout 或流量策略**
1. 投影：healthy→healthy、anomalous→degraded、unknown→unknown（带原因）、cancelled→cancelled；pending/observing 不是终态标签；HTML、JSON 与 `release_outcome_from_durable` 三处一致。
2. HTTP 控制：带 `expected_control_generation`、幂等键、Origin；陈旧代际 → 409 `CONTROL_CONFLICT` 且状态不变；同键同参重放返回原结果；同键异参 → 409；终态 → 409；缺 Origin 或跨站 → 拒绝且不写；action 为 approve/block/rollback/promote/deploy → 400 且不写任何行；cancel → cancelled，之后零采样。
3. 代码面：路由集合仍满足 F7 规则（无路径含 MUTATION_WORDS）；发布控制动作集合恰为 {pause, resume, cancel}；`opspilot/` 包不导入 Kubernetes 客户端、不调用 `kubectl`／子进程、无 GitHub/CI API 客户端；Observer 的出站 HTTP 只有 Prometheus 只读源。
4. 权限负向：web／Observer／worker 角色对发布身份与版本列、校准列的非法写入被拒（42501），worker 对发布表无权限；三个产品入口不读取 `KUBECONFIG`、K8s service account token、CI/GitHub token 类环境变量（静态核对入口的配置读取）。
5. 全局挂起期间 observing 发布零查询；解除后不自动恢复。
