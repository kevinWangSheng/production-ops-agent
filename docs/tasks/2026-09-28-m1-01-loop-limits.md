# M1-01 调查循环去预算脚手架（对齐上游）

## 目标

用户 2026-09-28 决定：去掉每 Run 的预算类限制，只保留一个防循环上限，循环行为对齐上游 HolmesGPT（默认 `max_steps` 100，`holmes/config.py:112`；只有达到上限的最后一步才去掉工具强制回答，`holmes/core/tool_calling_llm.py:1161`；平时由模型自己决定何时停止调用工具并回答）。原因：每 Run 4 次模型请求、最后一次固定留给报告、20 次工具、240 秒工具时长等上限，加上系统提示里的预算句，使模型只有 3 轮查询且每次都被强制结束、写报告时看不到工具定义；这些上限源自 M0 成本控制与 v4 包 2026-09-13 冻结，属于预算脚手架，不是产品红线。

- worktree：`production-ops-agent-window-points`，分支 `feature/m1-01-window-points`（在已有改动之上继续；PR 拆分待 #57 合并后决定）。
- 独立审计（Codex，进行中）会逐项列出全部限制类规则与上游对照，结果另行处置。

## 行为合同

L1. **唯一的调查上限**：每 Run 模型请求上限默认 100（与上游 `max_steps` 默认一致）。除最后一次外，每次请求都携带工具定义；模型返回不含工具调用的回复即视为报告（沿用现有提前作答路径与报告校验、修复重试）。只有当剩余请求只剩 1 次时，才走现有的强制最终报告路径（去掉工具、追加 `FINAL_REPORT_INSTRUCTION` 与运行级覆盖消息）。
L2. **去掉每 Run 工具上限**：取消每 Run 工具调用次数（20）与工具累计时长（240 秒）的限制；单次工具调用超时、结果字节上限与视图截断不变（它们防单次调用卡死或数据爆量，不限制调查步数）。
L3. **输出上限**：单次模型输出上限由 16384 调到 65536（DeepSeek thinking 模式默认 64K，https://api-docs.deepseek.com/api/create-chat-completion/ ）；上下文上限 131072 与现有压缩机制不变。
L4. **Run 总时长**：1800 秒改为 7200 秒，只作为卡死兜底（ADR-0005 的超时清扫仍按此工作）。
L5. **提示词**：删除系统提示开场中的预算句 "You have at most {steps} model requests and twenty tool queries; the last request is reserved for the final report. Gather multiple useful independent queries per turn."，替换为一句 "Use the tools as needed until the evidence is sufficient, then return the report."；其余提示词不在本项改动。
L6. **冻结文档同步**：`opspilot/investigation/limits.py` 模块说明、v4 包 `docs/testing/first-investigation-v4-2026-09-10.md` 资源上限段（追加 2026-09-28 用户决定，原文保留）、`AGENTS.md`「费用与真实调用」一段中"保留的是技术上限"一句改为"每 Run 只保留一个防循环上限，以及单次调用超时与数据大小保护"（用户 2026-09-28 授权修改）。`runner.py` 的 `within(M1_FROZEN_LIMITS)` 检查保留，按新值生效。
