# #851 合同预审：常驻指令读取失败的输入标记

- 范围：issue #851（并入 PR #847 / 功能 #780，Run 输入 v9 尚未进 `main`，可在 v9 内扩展）。
- 预审者：未参与实现的全新上下文 Agent，对照 `poa-780-impl` 在 `49fdbebd` 的真实代码。
- 现状（已核查）：`opspilot/web/service.py` `_standing_instructions` 捕获 `(PersistenceError, DatabaseError, OSError, TimeoutError)` 后只记日志并返回 `None`，输入里没有 `standing_instructions` 键，与「目标没有常驻指令」逐字节相同。先例：`unavailable_catalog`（`knowledge/catalog.py`）、`unavailable_fact`（`knowledge/hints.py`）把同类失败写成 `status: "unavailable"` 的事实。
- 用户门：无。不扩权、不碰 PRODUCT-CONSTRAINTS、无不可逆项（v9 未发布）。以下全部按推荐由 Agent 落实。

| # | 语义点 | 选项 | 推荐 | 理由 |
|---|---|---|---|---|
| 851-1 | 标记放哪 | a 同一键 `standing_instructions`；b 新键 | a | 与目录、知识先例一致：同一事实键承载 ok/unavailable 两态 |
| 851-2 | 标记形状 | a `{"policy_version": "opspilot-standing-instructions-v1", "status": "unavailable"}`，正常事实六键不变；b 正常事实也加 `status: "ok"`，失败态其余字段填 null | a | 正常事实形状已被 #780 测试钉住；标记没有可填的内容，null 字段只增加校验面。先例里 null 字段源于其 ok 形状本就有 `status` |
| 851-3 | 原因码 | a 不记；b 记 `TIMEOUT` 等 | a | 先例都不记原因；日志已有；避免把错误细节带进输入 |
| 851-4 | 哪些异常算失败 | 同 `_runbook_catalog` 的四类异常元组；其余照旧向上抛 | 照抄 | 先例一致，不扩大吞异常的范围 |
| 851-5 | 开关关（`runbook_catalog is None`）或目标无指令 | 不写任何东西 | 照旧无键 | 「不读」与「读到空」都不是失败；无指令 Run 的输入、消息、`prompt_revision` 必须与 #780 前一致（B4-10） |
| 851-6 | 输入版本 | 带标记即 v9（`version` 按键存在判定） | v9 | v9 未发布，无兼容负担；旧构建本就不读 v9 |
| 851-7 | 校验器 | 键集合精确等于 `{policy_version, status}` 且 `status == "unavailable"`、`policy_version` 等于常量；否则须为原六键正常事实 | 如左 | 多键（标记混入 `content`）、`status: "ok"`、缺键、错版本都拒收 `INPUT_INVALID`，与先例的严格校验一致 |

| 851-10 | 后继 Run（follow-up / new_run） | 每次重读，不继承；重读失败写新标记，成功写正常事实 | 照抄 780-7 | 目录、知识都重读不继承；标记不应遮住之后恢复的读取 |
| 851-11 | 工作台展示 | 不展示 | 不展示 | 目录、知识的 unavailable 均无页面展示；本 issue 只要求输入可区分。需要展示另开 issue |
| 851-12 | 脱敏与大小上限 | 不适用 | 无 | 标记不含文本 |
