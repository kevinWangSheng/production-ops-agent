# M0 技术验证执行计划

日期：2026-09-07。状态：**P2 已完成隔离上下文的独立全文复审，用户授权修补并持久化；实验尚未执行。**

本计划落实 [C3 技术方案](../design/technical-proposal-2026-09-07.md)，不重新选择产品或架构。入口条件以 [SPEC](../../SPEC.md#conditions-for-entering-implementation) 为准；原功能验收由 [feature_list.json](../../feature_list.json) 维护，本计划不修改验收步骤或 passes。[审查记录](../reviews/m0-plan-adversarial-review-2026-09-07.md)记录两项补齐及全文复审结论。

## 目标与阶段边界

M0 以有界设计验证取得实施所需证据。目标仍是求职用途的有效、持续运行、只读运维调查 Agent，完整首版保留事故和发布后入口、人工控制、独立恢复观察及审核知识。

M0 验证关键机制，不要求先实现完整产品。完整 UI、全生命周期集成、全部故障覆盖、正式候选保留集评测和 72 小时 soak 在 M1–M3 完成。安全和观测从首条运行链路开始，不能后补。已有架构和约束无需二次确认。

以下八个工作包当前均未执行；“通过标准”是计划，不是通过声明。

## 1. 实验合同与证据

每项实验在执行前记录问题、前提、版本、操作步骤、预期结果、通过/失败判据、证据位置和失败处置，并映射 C3 条款及活动功能验收。

明确该实验只验证机制还是覆盖产品验收的一部分。例如恢复实验检查已提交响应/证据保留、未完成操作有界重试、迟到结果拒绝采纳、预算跨重启延续。

产出：实验清单、可复现脚本/配置、版本清单及结果记录格式。证据不足单独标记，不能算通过；不要用框架返回成功、trace 完整或模型自述替代外部状态判定。

## 2. 模型与框架兼容

核查并锁定 DeepSeek 实际可用 profile 和依赖版本，验证真实多轮工具调用、流式中断、工具错误后的续接、受限协议字段持久保存和恢复续传、上下文压缩后的工具消息配对。

检验 LangGraph 在当前业务日志恢复架构中的实际编排收益。先验证选定路线，有具体缺口才修补适配器；不为比较而先建设多套完整运行时。

产出：兼容矩阵、脱敏协议记录、可重复脚本及明确失败记录。通过依据是实际协议链路符合 C3；私有协议字段不进入报告、知识、LangSmith 或 judge。实质改变底座时修订完整设计并复审。

## 3. 持久恢复、人工控制与升级兼容

使用可控模型替身精确制造断点，再以实际 DeepSeek/PostgreSQL 组合校验关键链路，分别标明替身机制证据和真实组合证据。

实验覆盖：

- 模型响应提交前后、工具结果提交前后、结论发布前后的进程中断。
- 数据库短暂故障、租约过期/重派、并发预算及重启不重置预算。
- 人工暂停或关闭时旧调查返回。
- HealthProfile 变更时旧观察返回，以及迟到/乱序采样。
- 发布异常转事故与既有事故人工接管的竞争。

**升级兼容实验不可遗漏：**保留未完成 Run，在兼容版本下按相同业务合同重建；模型协议、工具 schema 或业务状态不兼容时进入 `blocked(INCOMPATIBLE_STATE)`，原记录保留，不得静默换版本续跑。验证显式新 Run 继承允许业务事实的接续路径，以及停止领取、drain 或 pause 的前提。这里只验证有界兼容机制，完整发布升级演练仍在 M3，不建设多版本滚动平台。

产出：断点矩阵、操作/证据/控制版本时间线、重建与阻塞记录。通过依据是实际已提交状态、当前授权、预算及历史证据保持 C3 不变量，不承诺外部查询 exactly-once。

## 4. 真实环境与权限

固定 OTel Demo 版本与组件，先验证正常遥测前提：实际可查询的日志、指标、trace、资源和发布记录，其来源、目标/版本标签、保留窗口及 HealthProfile。

建立可复现的流量、发布、故障与环境重置。故意缺测单独标注，不能用未装好的环境充当缺测成功案例。Agent 只读身份与工程故障注入身份分离，注入答案不得进入调查上下文。

权限验证必须取得实际凭据作用域、网络可达性和数据库权限的拒绝证据，覆盖错误目标及秘密出站边界，不能只看配置名称或模型拒绝。

产出：接入清单、正常性检查结果、故障/恢复/重置脚本与权限证据。通过依据是查询数据、精确身份、可解释正常状态和独立故障确认成立，并且未授权操作被系统实际拒绝。

## 5. 上游基线与 eval 校准

固定 HolmesGPT 版本、配置、模型和工具，实际运行并建立复用/适配/扩展映射。细化 `IncidentScenario -> IncidentOutcome`、开发/保留案例、知识/反馈/初始状态和各类版本快照。

执行协议必须包含：

- 上游和候选尽量匹配模型、权限、工具和预算；无法匹配的差异逐项披露为实验因素，不能伪称同条件比较。
- 可诊断性由 Agent 实际可见证据预先判定，不依据注入器答案。
- 失败和放弃进入对应分母，缺证据集另评准确交接。
- 正确定位/因果及证据支持为主质量；速度和成本不能抵消不可接受的质量退化。
- 用开发基线校准并冻结案例规模、重复次数、统计方法、评分 rubric、质量门槛和非退化规则；正式候选评测前冻结，不能看完成绩再改标准。
- 报告质量 judge 使用人工标注校准，争议保留人审。
- 保留集不参与 prompt/知识调优；知识积累收益单独实验，防止跨实验污染。

产出：上游运行工件、差异说明、评分链路和冻结的评测协议。M0 证明环境及评分方法可用，不要求正式候选保留集结果，也不以开发小样本宣称普遍效果。

## 6. Trace、审计与平台

从第一条真实模型链路接通允许字段的 LangSmith 导出，验证主体/Run/attempt 关联、从评分追溯步骤/证据/版本、导出前私有字段和凭据过滤、平台不可用时业务完整及恢复导出，以及实验数据/结果导出复现。

PostgreSQL 仍是审计真相。产出为脱敏轨迹、业务记录关联和出口/平台故障证据；trace 成功不等于调查成功或权限验证通过。

## 7. 资源、费用与运行安排

先盘点现有本地资源，机制实验本地优先，完整工作负载按需安排隔离 Linux 环境。记录 CPU、内存、磁盘、模型用量和平台费用，明确启停与资料留存。

1000 元是可调整的项目预算参考，不是采购授权。具体新增支出提供用途、金额/上限和期限供审核；已取得实际授权的范围内不重复询问，不能将预算参考冒充授权记录。

已批准数据用途不重问；新增私有来源或扩大出口用途时明确范围。沿用不做硬盘灾备的约束，不承诺常驻双 VM、HA 或当前预算必然足够。撤销环境前保留应留工件，不擅删唯一数据。

产出：资源实测、费用推算依据、具体运行安排与需要时的采购方案。

## 8. 退出与实施交接

每项实验记录通过、失败或证据不足，以及可复现版本/工件、问题处置和影响的实施任务。

实现缺陷修复后重测相关机制及受影响链路；实质设计修改合并完整方案后重新全文对抗性审查。未解决的关键前提不能跳过，也不能以 mock 冒充真实验证。

M0 为对应实施工作提供兼容证据、数据源/权限映射、校准后的验收包、资源测量、依赖版本、任务拆分与投入估算。按 SPEC 更新具备证据的入口状态，不要求全产品验收先通过，也不将机制实验自动登记为功能完成。

## 执行顺序

1. 实验合同与环境正常性前提。
2. 上游真实调查基线、模型协议验证独立推进，同时接通 trace。
3. 关键恢复、人工控制、升级兼容与实际权限验证。
4. Eval 校准和资源测量汇总。
5. 汇总证据，形成对应实施入口及任务安排。

独立工作可并行，不因设施追求完美而无限推迟真实调查。详细脚本、版本、用例和本地隔离方式由助手负责。

## 决策归属与当前状态

已批准的目标、范围、技术方向及约束不再重复讨论。只有尚未授权的具体支出、新数据用途、实质产品/架构变更，或证据揭示的质量/时间/成本冲突，才需要用户判断。

P2 全文设计审查通过，不代表模型兼容、容量、费用或效果已验证。当前仅完成规划持久化，全部实验及功能验收仍待执行。
