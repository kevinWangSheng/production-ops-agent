## 读者与页面任务

读者是没见过产品的资深工程师，要在五分钟内看懂一次事故：出了什么事、Agent 的结论是什么、结论靠哪些证据、恢复了没有、人做过什么。

每个页面先写清楚一句「这页帮读者完成什么」，再决定放什么内容。回答不了这句话的内容不放首屏。

页面分两类。**阅读页**（事故详情、证据、知识条目）读者从头读，规则按下文。**分拣页**（事故列表、版本变更列表、复盘审核）读者先扫视、再挑一处细读，另外适用「分拣页补充规则」（规则 13、14 及规则 3、4、7 中标明分拣页的部分）。

## 取值

### 颜色

一套中性色，一个强调色，一个错误数据色。不再增加色相。

### 字体与字号

### 间距与版式

- 页面最宽 1440px，左右留白 32px（窄屏 16px），上 24px，下 56px。
- 顶栏高 52px，白底，下方一条 `--line`。
- 详情页两栏：主栏自适应，侧栏 352px，栏距 64px；侧栏随整页滚动，不吸顶、不做内部滚动（侧栏内容常高于一屏，内部滚动会藏住入口）。1180px 以下合为一栏。
- 满宽表格页（目前只有事故列表这类多列分拣表格）不用侧栏：表格占满页宽，人工提问、其他控制、状态说明三块放在列表下方，1180px 以上三块并排，以下纵向排列；页面标题右侧放一个次要按钮「Ask OpsPilot to investigate」，跳到下方表单并展开。其他带侧栏的页面保持两栏，同样不吸顶。
- 区块之间：上方一条 `--line`，线上 32px、线下 28px。首个区块无线。
- 行内条目之间：一条 `--line` 加 7–12px 上下留白。
- 圆角：量条和色块 2px，按钮和输入框 5px，药丸全圆。
- 阴影只用于右侧证据抽屉。
- 断点：1180px（两栏变一栏）、720px（窄屏）。

## 规则

1. 不用彩色顶边、彩色侧条。
2. 分组靠间距和细线。不给每块加边框，不在框里再套框。
3. 每个状态只有一个权威位置，给出判定、依据和来源。摘要带可以用一句话复述并链接到它；时间线只记事件发生的时刻，不复述状态的依据。同一状态在不同位置的措辞逐字一致。分拣页可以在页面顶部用一句分拣摘要或一个清单列出需要处理或核对的条目，并链接到它们的权威位置；只列条目、数量和原因词，不复述依据。
4. 阅读页首屏（1440×900）药丸不超过四个。分拣页每行或每个待决对象可以有一个状态标记，不计入此数；除此之外不再加药丸。
5. 全页最大的正文回答「这页帮读者完成什么」：阅读页是结论句，要人做决定的页面是任务句。告警名是标题下的安静副标题。
6. 时间线是第三层信息：无外框、无角色标签，只有记号、时间、一句事件。
7. 每条陈述都能看出是谁说的（告警源、Agent、代码检查、人）。阅读页用来源记号加文字；分拣页的表格行里只用文字（Operator、Agent、Observer），不放来源记号，行首留给状态标记。
8. 调查报告与恢复判定是两个独立结论，分开摆放、分别标明来源。报告不证明恢复。
9. 不编数据。没有的值用斜纹或「无数据」文字标明缺失，不留白、不估值。
10. 产品是只读的：页面只出现后端当前状态允许的操作，不画产品没有的写操作。
11. 颜色不单独承载含义，同时有文字或形状。键盘焦点有 2px 强调色外框。
12. 三个宽度都要成立：1440、1180 以下、720 以下。宽表格和图表在自己的容器里横向滚动，页面本身不横向滚动。

### 分拣页补充规则

13. 分拣页：需要人处理的条目排在最前并单独成组，组标题带数量；空组不画，只出现在分拣摘要里。已结束的条目显示的字段行数不多于需要处理的条目，结论摘要最多一行。
14. 通过的检查只在所属区块说一次；逐行只标例外。

分拣页的人话状态和待办药丸加在系统原词前面，不替换原词。「需要人」不加独立色相，靠待办药丸的墨色实底区分；已结束的条目默认展开（按基线稿 r2）。

## 出稿与评审

- 每张静态稿用同一次真实 Run 的数据，数据逐项对得上记录。
- 每页至少覆盖：正常态、空态，以及该页特有的降级态（调查进行中、等待人工、无结论、调查不完整、数据已按保留期清理等）。
- 稿间链接：真实状态里指向另一页的入口链接到对应的稿；目标稿画的是另一条记录时就地注明仅示意跳转；示意态的示例行不放跨稿链接。出稿后把各稿连起来实际点一遍。
- 状态怎么画：有真实记录的状态用真实记录画。没有真实记录、但会改变页面骨架的状态画成示意态，值全部用缺失表示法留空，示例行就地标明「example row」，不放看起来像真实值的占位值。只多一行或一个标记的状态不单独画，在稿子的设计备注里写明它出现的位置和触发条件。
- 出稿后自己截图检查三个宽度，再交未参与出稿的全新上下文评审者，评审对照本文规则、页面任务、产品约束和现有模板；数据另由独立核对者逐项对原始记录。出稿者和协调者的自检不算评审。静态脚本检查不能替代渲染：改过版式的稿必须实际渲染三个宽度后才算验证过。

## 已定（原「待定」，用户 2026-11-16 裁决）

- 深色主题：不做；去掉设计稿顶栏的主题切换占位。
- 界面语言：保持英文；版本变更详情页的中文固定提示原样保留（合同 D4 的固定文案，被验收测试逐字断言）。
- 设计稿不再细化：实现以基线三张稿和本文为准，细节由实现者按本文规则自定。
