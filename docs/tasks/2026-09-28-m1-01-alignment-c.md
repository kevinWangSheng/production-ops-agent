# M1-01 第三批：去掉过时规则、修复反馈具体化、trace 分组摘要

## 目标与来源

第二批效果测量（[证据](../evidence/m1-01-alignment-b-effect/run.md)）：核心 4 场景 P2 由 14→10→8，剩余以 e 类（区间/计数/来源）为主；并发现两处与合同不符。用户 2026-09-28 决定做第三批：

- 系统提示 `replay-candidate` 变体仍含 `FIXED_WINDOW`："The authorized query window is fixed by the trusted runner; do not supply start/end tool parameters."（`opspilot/instructions/discipline.py`），与第二批 B2 工具参数矛盾。
- B3 修复反馈只给固定原因码，合同要求写明哪条 claim、哪个 evidence_id、何种错误。
- e 类错误：重放实验（[证据](../evidence/m1-01-replay-ablation/README.md)）中"代码算好的分组摘要"对 e 类最有效（组 3：20→5），属"计算交给代码"，与上游"在数据源计算"的思路一致。本批不加规则句（a 类已降到 2），看数据再定。

## 行为合同

C1. **删除过时规则**：只在实际使用的 `replay-candidate` 变体中删除 `FIXED_WINDOW` 句；历史 baseline 变体按原有字节锚定保持不变；`prompt_revision` 随之变化。
C2. **修复反馈具体化**：报告解析或引用校验失败时，反馈消息逐条列出失败项：claim 序号（从 0 起，按报告 claims 顺序）、该 claim 引用的出错 evidence_id（若有）、错误类型（使用校验器已有的规范化原因名，如引用未交付 id、引用非 ok 或 `citable_as_fact=false` 视图、缺少 target/time 引用、JSON 解析失败的位置描述）；按 claim 序号排序、去重，最多列 50 条并注明是否截断；不含任何视图原始内容。仍只允许 1 次修复（与 L1a/B3 相同）。模板计入 `prompt_revision`。
C3. **trace 视图分组摘要**：每个 traces_search 视图新增 `span_groups`：按视图中**已展示**的行的 `(service, operation)` 分组，每组给出 `rows`（行数）、`status`（计数：有状态标签时按键值对计，如 `"rpc.grpc.status_code=0": 13`；`status_state=not_recorded` 的行单独计为 `"not_recorded"`）、`error_rows`（`error_by_visible_tags` 为 true 的行数）、`duration_us_min`、`duration_us_max`；组按 `(service, operation)` 排序；只由已展示行计算，被截断/省略的行不参与，并在视图中用一句字段说明写明"只汇总已展示行"。算法与重放实验 `docs/evidence/m1-01-replay-ablation/scripts/span_groups.py` 一致（实现时核对并记录差异）。`span_groups` 计入视图哈希与字节上限；工具描述补一句说明。
