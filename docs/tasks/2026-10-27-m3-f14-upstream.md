## 第 1 步实现（#396，对齐 r1）

做了什么（行为）：
- lab 只读代理新增 `holmes` 账号：只有它能对 `/api/v1/query`、`/api/v1/query_range` 发 POST 表单体（≤64k），其余账号保持 GET/HEAD、不转发请求体；`metadata`/`rules` 仍 403。只记 holmes 账号的访问日志（不含头、参数、请求体）。`kind_lab.py proxy` 只重渲染并滚动代理。F7 探测在冻结矩阵之后追加 holmes 行。

可逆技术细节（Agent 自定，一行理由）：
- Holmes 用的代理密码以 `{{ env.HOLMES_PROMETHEUS_AUTHORIZATION }}` 占位，经 `docker run -e NAME` 从调用方环境传入：配置文件里没有秘密，比 R9 的「写进只读配置」少一处落盘。
- 64k 上限设在 server 级：nginx 在命名 location 里不按 Content-Length 校验上限，只有 server/精确 location 级生效；对其他账号的效果是 >64k 的请求体得到 413 而不是 403，仍是拒绝。
- POST 规则另要求 `Content-Type: application/x-www-form-urlencoded`：Holmes 的查询就是表单，收紧不影响它。
- 输出上限用 `OVERRIDE_MAX_OUTPUT_TOKEN=65536`、上下文用 `OVERRIDE_MAX_CONTENT_SIZE=1000000`：a0009195 里 `MAX_OUTPUT_TOKEN_RESERVATION` 只读不用（`holmes/common/env_vars.py:118` 无引用），U6 写的变量不生效。
- Prometheus 查询默认与硬上限都设 30s（OpsPilot 单工具 30s）；http 工具集 30s。
- Jaeger 路径白名单取 `jaeger_url` 的路径加 `/api/*`（lab 为 `/jaeger/ui/api/*`），并在 `llm_instructions` 写明基址与三个 GET 端点（配置，不是代码）。
- 隔离网络：Holmes 只挂 `--internal` 网络；中继容器同时在 `kind` 网络，只转发 9090→节点 30090、16686→节点 30686；出口代理在默认 bridge，只放行 `CONNECT api.deepseek.com:443`。两者都是 stdlib Python，跑在构建已拉取的 `python:3.11-alpine` 上。
- 镜像用 VM 内 `docker buildx build --load`（宿主 docker CLI 无 buildx，旧构建器不设 `TARGETARCH`，未改 Dockerfile、无 build arg）。
- 上游 checkout 在主仓库 `tmp/upstream/holmesgpt-a0009195`（R1）；原始输出在主仓库 `tmp/f14-holmes/`。

- 输出预算以外，温度设 `TEMPERATURE=none`：OpsPilot 请求不带温度，Holmes 默认 1e-8。
