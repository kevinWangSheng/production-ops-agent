| 观测数据 | 设施用管理员 kubeconfig 做 port-forward：Prometheus pod 的 9090（上游 `listenLocal`）、`svc/jaeger-collector` 16686；ClickHouse 日志**未集成**（产品无对应工具，A564-9） | 上游文档的访问方式；产品只拿到回环地址 |
| A564-3 答案 | Lite 的 `convert_run` / `answer.convert`；词表按 Lite 规则从集群列表（注入前 + Run 后合并，只读身份读取）和 Jaeger 服务名生成 | 不改产品报告格式 |

## 冒烟的主机命令（租机空闲后执行；以 opspilot 用户，`HOME=/home/opspilot`）

ITBench 已在 `/home/opspilot/itbench-live/ITBench` 钉住 `5ed31cc4`，`uv sync --no-dev` 与 ansible collections 已装（2026-11-24，`itbench --help` 正常）。

```sh
# 0 前提：停掉主机上其他 kind 实验（preflight 会拒绝），确认 free -m 有 ≥16 GB 可用
# 1 mise 与 kind 环境集群（上游 clusters/kind/README.md）
curl https://mise.run | sh && export PATH=$HOME/.local/bin:$PATH
cd ~/itbench-live/ITBench && mise trust && mise -E kind install
mise -E kind run create:kind:environment     # 1 控制面 + 2 worker，Cilium
nohup mise -E kind run run:kind:provider > ~/itbench-live/provider.log 2>&1 &   # LB 地址（未核实是否必需）
export KUBECONFIG_ADMIN=$HOME/itbench-live/ITBench/clusters/kind/kubeconfigs/kind-environment
# 2 OpsPilot 检出（运行 checkout 检出本 PR 合并后的 main）
cd ~/production-ops-agent
.venv/bin/python -m scripts.itbench_live.driver preflight --itbench ~/itbench-live/ITBench --kubeconfig $KUBECONFIG_ADMIN
set -a; . ~/rental-private/lite.env; set +a     # DeepSeek、LangSmith、ZAI_API_KEY、ITBENCH_EVALUATIONS_DIR
.venv/bin/python -m scripts.itbench_live.driver round --round live-smoke-<MMDD> \
  --itbench ~/itbench-live/ITBench --kubeconfig $KUBECONFIG_ADMIN \
  --env-file ~/rental-private/lite.env --scenarios 20,23 --trials 1
.venv/bin/python -m scripts.itbench_live.driver scores --round live-smoke-<MMDD>
# 3 收尾：mise -E kind run destroy:kind:environment；停 provider 进程（按自己记下的 PID）
```

资源与时间（推断，未实测）：集群 3 节点，上游最低 8 CPU / 16 GB / 50 GB；每题 = 部署 15–30 分钟 + 告警等待 ≤20 分钟（上游规则 `for: 5m`）+ Run ≤ 2 小时上限（Lite 实际约 10 分钟）+ 清理 5–10 分钟，约 45–75 分钟一题；建集群一次约 10 分钟。冒烟 2 题约 2–3 小时。

## 未核实（冒烟第一次验证）

上游 `deploy environment` 全量部署（含 agents、recorders 两步）在本主机的耗时与成败；agents 步骤装的准入/网络策略是否影响我方 RBAC 清单与 port-forward；cloud-provider-kind 是否必需；Prometheus pod 名与 `svc/jaeger-collector` 名、Jaeger 查询的路径前缀（设施依次试 `""`、`/jaeger`）；告警是否带 `service_name` 标签；`inject faults` 返回时故障是否已生效（上游 waiters 可能延后注入）；评测器对 live 答案格式的判分表现。

## 冒烟发现（2026-11-25）

- 上游 Jaeger v2（ClickHouse 存储）只提供 v3 查询接口。产品的 trace 工具调用 v1，本轨 trace 记为「未集成」。设施改为识别这种情况并标 `JAEGER_V1_API_ABSENT_V3_ONLY`。
- 首条新告警是 `KubePodNotReady`，不带 `service_name`，目标按 alertname 退回匹配。
- 只读 RBAC 不覆盖 endpointslices 和 limitranges，词表缺这两类，不扩权。
- 上游建集群的任务需要先导出 `KUBECONFIG`，否则 Cilium 装不上。
