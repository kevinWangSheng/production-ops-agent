## 待裁决（回复「yes」即全部接受推荐；逐条改也可以）

**Q1 M2 是否现在宣告完成？**
推荐：是。七项验收都已真实通过，符合 C3 的 M2 退出条件。#244/#245 照现有裁决继续，不算 M2 门槛。M2 期间留下的小问题（#358 #359 #365 #366 #290 #230 #256 #268）进入 M3 待办，只有挡住 M3 验收的才做；#290（DNS 线程累积）和 #325（死 pod 序列不过期）会让 72 小时运行失真，排在 soak 之前修。

**Q2 M3 按什么顺序做？**
推荐四段，前两段可以并行：
1. 交付底座（F9）：产品镜像、一键安装脚本、版本号与 tag、README 重写。之后的 soak、升级、基线都要靠固定镜像来跑，所以排第一。
2. 上游对照（F14）：把 HolmesGPT 固定成容器镜像跑通，写逐功能映射表。和 1 互不依赖。
3. 运行可观测（F8 第 1–3 步）：健康端点、外部告警、#243 产品 trace、结构化日志、带在途事故的升级与回滚演练。
4. 评测与收口（F1 + F14 第 4 步 + F8 第 4 步 + F9 全流程）：场景集 v2、保留集、judge、同条件基线对比、72 小时 soak、作品集文档。
代价：评测排在最后，期间不再出质量数字。理由是 judge 口径（Q7）和保留集（Q9）要先定，而且基线必须在固定镜像上跑。

**Q3 72 小时 soak 和 staging 在哪台机器上跑？**
推荐：租一台 Linux 云主机，规格按 C3 §12 候选值（控制侧 4C/8G 加目标侧 8C/16G，可以合成一台），soak、staging 和「干净机器安装」验证都在这台上做，用完导出证据再释放。本机 16 GB 在 lab 运行时 swap 反复接近满，M1 首次端到端就因宿主内存失败过，扛不住 72 小时。代价：要花钱，费用从 C3 §12 的基础设施额度出；下单前我先给具体机型和报价，由你批准。替代方案：本机跑缩小规模的 soak，并写明「本机受限、非 72 小时」，这样 F8 第 4 步达不到原文要求。

**Q4 产品怎么交付？**
推荐：一个产品镜像（发布到 GHCR，按 digest 固定），web、worker、Observer 共用；用 Helm 部署进 kind 实验环境作为 staging，不另做 Compose。「干净机器」定义为全新 Linux 主机，跑一个 bootstrap 脚本完成 PG、各角色、配置文件和 kind lab。macOS + colima 只保留为开发环境。代价：macOS 上的一键安装不在验收范围内。

**Q5 「外部探测」做到什么程度？**
推荐：给 web、worker、Observer 加只读的 `/healthz`、`/readyz`，报告 schema 是否在 head、队列深度、最近一次模型调用结果。lab 里的 Prometheus 抓取这些端点，Alertmanager 配两条规则：Agent 不在了，或模型连续失败。演练时停掉 worker、断掉模型出口各一次，看外部告警响起、Run 按合同交接给人。这些端点只读，不扩大任何产品权限。

**Q6 #243 产品模式 trace outbox 是否在 soak 前做？**
推荐：做。F8 第 1 步要求按事故和版本把 trace、指标、日志、成本串起来，现在产品模式什么都不导出。照 C3 §11 实现：业务事务和 outbox 一起提交，白名单字段导出到 LangSmith，积压有界丢弃并计数。数据出口规则（不导出凭据和 provider 私有字段）不变，导出目标仍只在合成 lab。

**Q7 judge 用什么口径算合格？**
推荐：按 #312 方案 1，合格门槛改成「结论（verdict）与人工标注一致 ≥ 46/48 且零误通过」，逐字段因果诊断降为复核材料；#300 不按现在的形态合并，能复用的部分（适配器修复）拆出来另提。依据：上次校准在有效输出上的结论一致率已是 40/41 和 46/47，失分主要来自两条超出 C3 原文的附加规则；Anthropic 明确反对评路径（A1「too rigid… overly brittle tests」），而「judge 必须枚举出每条标注原因」实质是在评路径；LangSmith 的 alignment score 就是二值判定与专家一致的比例（L5）。说明：三家官方文档都没给数值门槛，唯一的数字是 Braintrust 一篇文章里的「低于 80% 要改」（B7），46/48 是本项目自定、更严，不放宽。
代价：新 validation 集要两份盲标。改用 verdict 口径后，只有两份盲标在「过 / 不过」上不一致的题才交你裁定，逐字段差异不再需要你看（推断，依据 A1「两名专家应独立得出相同的过/不过结论」）；两份盲标彼此的一致率单独记录，作为题目是否清楚的参考。校准通过后，每轮评测抽几份 judge 判分做人工复核，防止漂移。
另外照上游加一道事后分诊：每轮评测的每个失败归为「评测 / 环境问题」「judge 误判」「真实失败」三类之一并引证据，前两类单独计数、不混进模型失败率（HolmesGPT `review-eval-run`，H4）。
不推荐的替代：完全照上游，只靠固定 judge、多次迭代和事后分诊、不做事前校准（H2–H4）。三家厂商来源都把「先与人工对齐」写成 judge 的前提（A1、B1、B5、L5），F1 第 5 步也要求人工复核校准；上游做法作为叠加项保留，不替代校准。

**Q8 上游基线怎么比？**
推荐：固定 HolmesGPT `a0009195`，打成容器镜像并记录 digest 和许可证，与 OpsPilot 用同一个模型、同一个只读代理、同一组预算上限、同一个已校准的 judge 版本，跑同一套场景。每个场景同时报两个数：单次通过率，和「k 次全过」的 pass^k；值班场景看重稳定，按 Anthropic 的说法用 pass^k（A1「pass^k for agents where consistency is essential」）。k 在开发校准后冻结（上游经验值是 10 次，H2；live 受 kind 串行和费用限制，预计取 3，样本小时把不确定性写在表里）。两边交替运行，每次记录环境是否洗净、故障开关状态和宿主 swap，避免一边总赶上机器压力大的时段（A1「each trial should be isolated」）。报告质量的成对比较（pairwise）只作辅助视图，不进主指标（L4、B5 都提示位置偏差）。容器运行同时关闭 M0 遗留的「Holmes 宿主 OS 隔离」（#93 子项）。对不齐的差异（例如上游没有持久任务）写成实验因素，不算 OpsPilot 胜出。

**Q9 保留集和场景集 v2 怎么出？**
推荐：场景集 v2 补齐 F1 第 2 步的六类（噪声、缺测、重复事件、模型故障、提示注入、错目标），每类配一正一反两题，例如错目标一题应拒绝或交接、另一题应正常调查（A1 要求正反平衡）；每题附一份能通过判分的参考报告，证明题目可解（A1「reference solution」）。出题照上游防作弊做法：故障里注入唯一可查的值、资源用中性名字、问题里不泄露指标名（H5）。连同现有 6 个场景约 18 题，接近 Anthropic 建议的 20–50 题起点下限，样本量有限照实写明。数据集分开发集、校准集、保留集三份并打版本标签（L1）。保留集由一个不参与调优的独立 Agent 在仓库外生成、自测可解后封存，答案只留在评测侧；你只批生成规则，不看题；保留集只在候选评测时打开一次，打开后转为开发集。每轮清单补 `runbook`、`dataset` 维度，基线轮填 `upstream`；录制缺陷 #283 #284 #327 在第一轮基线前修好；数值门槛照 C3，开发校准之后、候选评测之前冻结。另外，把评测分成两组分开报：回归组（现有各功能确定性验收与 CI 结构重放，应接近 100%）和能力组（judge 场景集，通过率偏低是正常的，用来指导改进），避免两种数字互相稀释（A1 capability vs regression；上游同样用 `easy`/`regression` 标签区分必须一直通过的题，H1）。

**Q11 线上评测做不做？**
推荐：不做线上评测、生产监控、A/B 和用户反馈这一套——它们都以真实用户和生产流量为前提，我们只有合成 lab，做了也是摆设。只移植一点：soak 和 kind 运行中观察到的真实失败，按失败模式归类，每类经审核转成一个开发集题目（B8、A1「从真实失败取题」）；这些题不进保留集。评测结果可同时上传到 LangSmith experiment 作对比界面（作品集展示用），权威结果仍以仓库 `summary.json` 为准（D7 不变）。

**Q10 M3 期间沿用什么授权？**
推荐：沿用 M2 剩余实施的规则（[Q1/Q5/Q6/Q12](2026-10-24-m2-remaining.md#授权与决策规则用户-2026-10-24)）：实施中的小取舍按推荐由 Agent 定、写进任务记录；功能 PR 满足就绪条件后（含翻 `passes` 的）由 Agent 合并并事后简报；真实运行失败且分诊为环境或模型随机性的，每场景预授权重跑一次。以下情况停下来找你：花钱（Q3 下单、soak 期间模型费用超过事先报价）；扩大产品权限或新增连接器；改 PRODUCT-CONSTRAINTS；削弱或改写验收步骤；judge 盲标「过 / 不过」分歧的裁定（Q7）。
