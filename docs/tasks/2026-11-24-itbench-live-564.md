## 冒烟发现（2026-11-25）

- 上游 Jaeger v2（ClickHouse 存储）只提供 v3 查询接口。冒烟当时产品的 trace 工具只调用 v1，所以 S20 的 trace 调用失败。#859（PR #864，`54ec3952`）之后，产品会自己先试 `/api/services`，再试 `/api/v3/services`。设施的 `JAEGER_V1_API_ABSENT_V3_ONLY` 只说明环境的接口情况，不再表示 trace 未集成；产品是否真正连上 v3，以 Run 的工具结果为准。
- 首条新告警是 `KubePodNotReady`，不带 `service_name`，目标按 alertname 退回匹配。
- 只读 RBAC 不覆盖 endpointslices 和 limitranges，词表缺这两类，不扩权。
- 上游建集群的任务需要先导出 `KUBECONFIG`，否则 Cilium 装不上。

## 全量前加固（2026-11-25）

24 × 1 无人值守前按独立审查加固设施（Agent 自定，可逆；分支 `chore/itbench-live-full-hardening`，worktree `poa-live-hardening`）：

- 驱动收到 SIGTERM/SIGHUP 时抛出不可捕获的中断，先跑完本题清理再退出，不写本题 summary：子进程各自成会话、PG 由 pg_ctl 后台化，原先只有驱动被杀，残留进程挡住续跑。
- 续跑时，没有 evidence summary 的旧题目录改名为 `trial-N.aborted-<UTC 时间>`：原先复用旧目录会因 PG 目录已存在而记成 `stopped`，从此被当作已完成。
- 启动的每一项连同 PID 立刻写进 `trial.json.partial`：驱动被 SIGKILL 时，人工能知道哪些进程可能还活着。
- 端口占用、`configure` 失败、缺沙箱污点、节点读不到属于集群级故障，直接停整轮且不记题；连续 2 题 `infra_failed`/`crashed` 也停整轮：集群坏了不该把剩下的题全耗掉。
- `configure` 前要求 `otel-demo` 与 `itbench-observability` 两个命名空间都不存在，否则 `ENV_NOT_CLEAN` 停整轮：保证每题都在干净环境上部署。
- `deploy` 失败时立即重试一次，中间不 `undeploy`，并披露 `DEPLOY_RETRIED`：2026-11-25 在新建集群上，首次部署约 3.5 分钟后失败，紧接着重跑成功（ansible 幂等）。
- `undeploy` 失败时重试一次，之后最多等 10 分钟让两个命名空间删干净；只有这一步仍失败才停整轮。`remove` 失败但 `undeploy` 干净时只披露，不停整轮。
- 判分子进程加超时：评测器调用 1800 s，判分进程 2100 s 兜底；超时按一次失败尝试重试。Lite 只多了一个可选 `timeout` 参数，行为不变。
- 等告警和等 Run 时检查 port-forward 是否还活着：断了重启一次并披露 `PORT_FORWARD_RESTARTED:<名>`，再断就停本题。`ALERTS_POLL_UNREADABLE` 只披露一次：Prometheus 转发指向 pod，pod 重建后转发会断。
- 入口告警只从 `activeAt` 不早于注入开始时刻的告警里选。注入前已有的标签集只在 `activeAt` 未变时排除：快照到注入之间激活的告警不会被当成入口，注入后重新激活的告警可以入选。
- `judge` 子命令跳过已判出 `ok` 的题，`--force` 才重判；`round` 续跑时，冻结了但还没判分的题会先补判：避免覆盖已有分数，也避免漏判。
- 上游 CLI 和判分进程各自起新会话，超时或中断时杀整个进程组：原先只杀 `uv`，它的子进程会留下。
- `memory_before` 旁边记录仓库所在文件系统的磁盘用量 `disk_before`：长跑时磁盘可能写满。
- 环境就绪之后、建只读身份之前留一个评测侧钩子 `_post_deploy()`。当前不做任何事，留给 #866 的部署后步骤。
