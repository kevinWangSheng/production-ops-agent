## 反馈回路（Q10）

出问题先分诊再处理；到上限就停该线、写进简报，其余线继续。失败轮一律保留，不算通过。

| 信号 | 分诊 | 自动处理 | 上限 |
|---|---|---|---|
| CI 失败 | 环境前提 / 代码 / flake | 环境就修环境；代码由实现者修；flake 走 flake PR | 同一 PR 连续 3 次红 |
| 独立审查 FAIL | 逐条 | 合同内的修，修完复验受影响项 | 2 轮 FAIL |
| 真实运行失败·环境 | 按下节 runbook | 恢复后重跑（Q6） | 1 次 |
| 真实运行失败·模型随机性 | 对照 trace | 不改代码重跑（Q6） | 1 次 |
| 真实运行失败·产品缺陷 | 可复现且能引用合同条款 | 开 fix PR（一 PR 一缺陷）→ 预审按推荐 → 独立审查 → 按 Q5 合并 → 新一轮验收 | 每场景 2 个修复循环 |
| 真实运行失败·测试写错 | 测试作者分诊 | 测试作者修，不放宽判据 | 1 次 |
| 需改验收步骤 / 扩权限 / 违背 PRODUCT-CONSTRAINTS | — | 不处理，停该线（Q1） | 0 |
| Codex / bot / GitHub 不可用 | — | 换模型或换审查者；bot 不阻塞；HTTP/1.1 重试 | 记录即可 |

驱动（Q11）：本机会话 `/loop` 自定步调巡检（子 Agent、PR、kind 占用、非 kind 线），kind 与本地 PG 都在本机，不用云端 routine。

## Runbook

- kind 计数器停滞：VM 重启后 span 计数器可能不涨。先查 frontend rate > 0；为 0 就 `rollout restart` otel-collector。
- 本机内存压力：观察 / 校准前查 `vm.swapusage` 与 memory_pressure；swap 满时 checkout p95 会升到 0.5–1.8 s。F11 harness 要求 swap 余量 ≥ 2048 MiB。只停本任务自己的进程。
- kind 观察窗内：不合模型可见 PR，不 merge main 后重启 worker，不跑 `make check` 或全量 pytest，不新开 Codex。
- Codex at capacity：换模型，中途断开用 session id 续跑；启动后看日志确认真起来了。PG 在沙箱外起，提交由 lead 做。
- 子 Agent：派发时要求前台短检查，不依赖后台等待通知。
- 红绿对照用 `git diff` 补丁加 `git apply -R` / `git apply`，不用 checkout / stash。
- 实施线同步用 `merge origin/main`，不 rebase；测试 worktree 不合并实现分支，合同改动用 cherry-pick 送进去。
- 删 worktree 前查 `git status --ignored` 与 `tmp/`，有 PG 数据或 ledger 先归档。
- 证据里的幂等键字段叫 `idempotency_label`；推送前扫本分支 secret。
